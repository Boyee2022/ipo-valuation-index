# 07 · 合规与治理：把边界写进协议

> 本文是设计约束与治理建议，**不是法律意见**；具体合规判断以公司合规/法务意见、监管规则与交易所要求为准。  
> 一句话原则：系统只做**研究参考与估值诊断**，不做定价、交易与政策决定；数据用途绑定，模型可解释、可回滚，决策人工在环。  
> 本文与 [00](00-evaluation.md) §8、[04](04-use-cases.md)、[06](06-evaluation.md) 共用同一套边界。

## 1. 监管语境

### 1.1 指数编制与发布

项目作者单位为中证指数有限公司（下称“中证指数”），指数编制与发布属于该机构职责；课题背景涉及上海证券交易所（下称“上交所”）的企业估值研究。指数编制方案（样本空间、选样、加权、定期调整）与正式点位发布由指数机构按既定规则负责，**估值系统不是指数编制系统**：它按成分权重把逐券估值合成为“拟合点位”，这是研究口径，不是官方指数点位。

由此有三条硬边界：不得以指数名义对外发布拟合点位；不得把拟合点位当作指数产品的跟踪基准；不得用估值结果反向影响样本调整、权重计算或正式点位发布流程。报告中“拟合点位”必须与“指数收盘”并列展示并标注口径差异。

### 1.2 交易所与上市公司信息

上市公司信息披露由交易所规则约束。系统只使用公开披露数据（行情、财报、公告、公开新闻/股吧），并遵守数据源的访问条款、频率限制与转载限制；不得使用未公开信息、内幕信息或通过非授权渠道获取的数据。课题来自上交所方向的研究，但系统输出**不代表上交所或中证指数的立场**，也不构成监管意见。

### 1.3 IPO 定价

IPO 发行定价受中国证监会及交易所发行承销规则约束（如《证券发行与承销管理办法》及交易所配套业务规则），涉及保荐机构与主承销商的核查责任、发行人与承销商的定价程序、面向网下投资者的询价、以及公平披露与静默期要求。系统在其中的定位只有一个：**研究参考**。

- 不参与询价，不替代保荐核查，不替代信息披露，不构成发行定价建议；
- 输出的估值区间与约束检查只供定价委员会、保荐机构与主承销商讨论，最终价格由人和机构按程序决定并签字负责；
- 涉及发行人的项目材料须按保密信息管理，遵守静默期与公平披露要求，不得选择性向外泄露或暗示定价结论。

公平披露与静默期是 IPO 项目的两条高压线：项目组不得向分析师、媒体、投资机构选择性透露估值区间或定价倾向；发行前静默期内，估值结论不得进入公开宣传材料。内幕信息知情人按公司制度登记，系统访问记录与知情人名单分开管理，二者交叉核对。

## 2. 数据合规

### 2.1 公开数据

公开数据也要守规矩：来源条款、访问频率、缓存与转载限制、不得转售或二次分发；每条数据记录来源与 as_of，报告“数据溯源表”可核对。舆情与新闻抓取须遵守目标站点条款与合理使用边界，不绕过访问控制。缓存、日志与临时文件同样属于数据：缓存带 as_of 与清理策略，日志不记录保密字段原文，临时文件任务结束即清理。

### 2.2 保密材料

IPO 项目材料（招股书草稿、问询回复、未披露财务数据、发行方案等）属于保密信息，处理原则是**用途绑定 + 最小必要 + 全程留痕**：

- **授权与用途**：只有获得项目授权的人员与任务可访问；材料只用于本次估值研究，不得挪作他用、不得进入公开模型训练、不得跨项目复用、不得对外提供；
- **最小必要**：只采集估值必需的字段，能脱敏则脱敏，能汇总则不保留明细；
- **权限与隔离**：项目级数据域、角色权限、独立缓存与存储，与公开数据通道物理或逻辑隔离；
- **留痕与审计**：谁在何时访问了哪些字段、运行了哪些任务、输出给了谁，全部可追溯；
- **保留与销毁**：项目结束按公司规定归档或销毁，保留期限与销毁记录可查。

### 2.3 现状差距

当前批跑服务（3089）**无鉴权、CORS 全放行、仅限可信内网**，报告与配置写在仓库外但无项目级隔离。这意味着它**不能承接真实 IPO 保密材料**。V3 之前必须补齐：身份认证与角色权限、项目数据域隔离、访问审计日志、脱敏与加密、静默期与对外发布控制；在补齐之前，IPO 场景只允许在脱敏样例与公开数据上做方法验证。

## 3. 模型风险与治理

- **可解释**：每券有方法树、参数溯源、证据链与敏感性；图的门控、被跳过节点、池化选择进入 trace；报告结论能回答“凭什么”。
- **可复核**：独立复算与双人复核；报告过 8 项机检；关键批次由未参与开发的人做抽样验证；机检失败即不可交付。
- **版本冻结**：模型 id、提示词版本、参数版本、数据 as_of、代码 commit 全部锁定并在批次快照中记录；模型或提示词变更须走审批与回归测试，不能“热改”。
- **回滚**：参数台账保留历史版本，`apply` 前保存 baseline，失败或指标异常时一键回退；回滚也需留痕。
- **人工在环**：评论家只提参数建议，主审裁决，人审批后才生效；IPO 定价由定价委员会决定；**不自动定价、不自动交易、不自动生成政策建议**。
- **持续监控**：上线后监控数据漂移、建议分布变化、采纳率异常；LLM 非确定性（温度、模型漂移）要记录并做重复运行方差分析。

按模型风险治理的通行做法设三道防线：业务与模型开发（第一道）、独立验证与模型风险管理（第二道）、内部审计与合规（第三道）。上线前由第二道验证，上线后由第三道抽查；换模型、改池化、改路由等重大变更须重新走一遍验证，不能只靠版本号自增表示“已更新”。

## 4. 利益冲突与公平性

- **不得对单一发行人/客户倾斜**：可比选择、证据门槛、参数 caps、区间规则对所有项目一致；不得因客户关系、项目压力或商业考虑调整；例外必须书面说明并经审批。
- **职责分离**：开发、验证、使用尽量由不同角色承担；评估者不能同时是唯一开发者（见 [06](06-evaluation.md) §8 的反循环）。
- **利益冲突申报**：参与项目的人员申报与发行人、承销商、投资机构的关系；盲评环节隐藏身份与建议。
- **审计与抽查**：内部审计/合规定期抽查数据访问、参数变更、报告口径与对外发布记录；异常访问告警；审计发现的问题闭环整改。
- **一致性**：同一发行人在不同批次、不同报告中的估值差异必须能解释（数据更新、假设变更、版本升级），不能出现无法归因的口径漂移。

## 5. “国家队/平准基金”表述边界

这是最容易越界、也最需要写死在协议里的部分。系统只做**估值温度诊断**：指数相对基本面偏贵还是偏便宜、偏离由哪些行业/风格贡献、置信度多高、证据是否充分。

明确禁止：输出或暗示“国家队应撤退/入场/平仓”“平准基金应买入/卖出”“建议监管采取某操作”等政策或交易指令；把估值诊断直接映射为操作建议；以系统名义预测政策走向。政策决策由有权机构按法定程序、结合更全面的信息作出，模型输出只是参考项之一，**不构成政策依据，也不代表机构立场**。

对外沟通时，诊断结论必须带口径、时点、区间与不确定性；不得断章取义引用为“官方判断”。若被用于政策讨论材料，须标注“模型诊断、非官方口径、不构成建议”，并由授权人员审核。

## 6. 免责声明与对外口径

### 6.1 标准免责声明

监控类报告统一声明：

> 本报告为内部研究性估值诊断，基于公开数据与模型假设生成，不构成投资建议、交易指令或政策建议；估值点位与区间为模型输出，受数据时点、假设与模型局限影响；报告不代表任何机构立场，未经授权不得对外发布或引用。

IPO 类报告统一声明：

> 本报告仅用于内部研究参考，不构成发行定价建议、投资建议或对发行人信息披露的替代；发行价格由发行人与主承销商按监管规则和程序确定；报告中的区间、约束检查与证据链仅供讨论，最终决策由有权机构作出。

### 6.2 对外口径

不对外发布指数观点；不宣称准确率、跑赢指数或预测点位；引用示例案例须标注“技能包示例、非指数回测”；媒体、客户与对外材料由合规与授权发言人统一口径，未经审批不得引用未公开结果。学术发表、演讲与对外交流涉及数据、案例或结论的，须提前报批；案例脱敏并标注“示例、非回测”，不得披露保密项目细节与未公开模型参数。

## 8. 残余风险与升级路径

- **规则与解释变化**：发行承销、指数编制、信息披露规则可能调整，系统与清单需定期复核，不能假定“今天合规等于明天合规”。
- **数据源条款变化**：公开接口可能变更条款或限频，需有替代数据源与降级方案。
- **LLM 生成内容**：可能产生不准确表述，报告须机检 + 人工复核；模型输出不得直接对外。
- **保密边界**：多人协作、外包、跨项目复用时最易泄漏，需权限最小化与审计兜底。
- **审计可追溯性**：文件级留痕在规模化后不足，V3 起应建设结构化审计日志与不可篡改存储。

升级路径：涉及监管解释、对外发布、重大模型变更时，先提交合规/法务评审，必要时与监管沟通；评审结论与限制条件写入使用范围，未解决前收缩系统用途。**能在制度上禁止的，不要只靠提示词约束。**

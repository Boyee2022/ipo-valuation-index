01

为什么现在要改

WHY NOW

现有系统已经能跑通五指数、多 Agent 评审与报告，但方法仍是“写在券内的固定流程”。 下面三条痛点不是“模型不准”，而是结构问题；三个机会也不是“再堆一层 Agent”， 而是把结构换掉——这正是本分支存在的理由。

P1 · 逐券全流程COST

一批指数 = 每只券各跑一次完整流水线。1 券 = 4 个脚本子进程（引擎 / 统计 / 报告 / 机检）； 上证综指 2,201 只 ≈ 8,800 次子进程量级。 同一方法在每张券里重复执行。

4 子进程 / 券 重复调度
P2 · 方法写死RIGID

DCF → 可比 → 舆情在券内串行；方法选择、权重与参数以固定流程和人工配置为主； 行业分位、可比池等跨券信息每券重算。想换一种合成方式，要改流程而不是换配置。

券内串行 人工配置
P3 · 评审散落SCATTERED

三专家 + 主审、shadow / apply 已可用；但评审发生在 pipeline 内部，参数只保留当前一版、 无跨批台账。“提议—裁决—回写”没有成为独立、可审计的一层。

无跨批台账 shadow / apply
结论先说 · VERDICT 方向是合理的，而且比“再加一层多 Agent”更有理论潜力；但必须换一个更严格的提法： 把“神经网络”当架构隐喻成立，当端到端可训练 / 反向传播不成立。 （00 · 评估）
三个机会 / WHERE TO START
OPP 01
可组合
模块有输入 / 输出类型、约束、版本、证据与不确定性；图可裁剪、可替换、可审计——从“固定流程”变成“可组合语义”。
OPP 02
可校准
门控与池化语义化（线性 / 对数 / 专家乘积）；用带合成目标的智能体评论家，把“人定参数”变成“有界、可回滚的参数更新”。
OPP 03
可复用
同一组模块服务已上市监控与 IPO 定价；数据域、证据域、合规域分离，迁移（domain adaptation / transfer）留作研究项。
02

前向图：类型化计算图

FORWARD PASS

前向不是“一个模型”，而是一张类型化计算图。每个模块是独立算子，有输入 / 输出类型、 约束、版本与参数 θm；每个输出不是单点，而是 点估值 + 区间 + 置信度 + 证据 + 审计轨迹。图可裁剪、可替换、可审计。

L0a · 前置采样 / 证据智能体 在编码之前，智能体团队做证据采集、核验、缺口补全与来源标注，产出 EvidenceBatch；它不改估值参数。后置评论家才改参数—— 前置“证据层”与后置“参数层”分开，避免证据同源与循环论证。

03

后向评论家：有界校准

AGENTIC CRITIC

后向不是“反向传播”，而是评审 + 有界参数更新。把多智能体评审写成一个独立层： 专家 = actor（提议），主审 = critic（裁决 / 夹断），shadow = 反事实对照， apply = 带信赖域的更新。

三专家提议可比质量 / 折现参数 / 舆情
证据门槛严重度 caps · 幅度上限
主审裁决accept / clamp / reject
shadow / apply留痕 / 回写重跑 / 失败回滚
参数存储版本化 · 可回放 · 可回滚
信赖域更新 · 带约束TRUST REGION
BOUNDED UPDATEδ* = argminδ∈C Lsynth(θ + δ; e) + λ‖δ‖1 C = { δ : |δj| ≤ cj(s), θ + δ ∈ Θfeas } θt+1 = θt + ηt · At · δt*

没有标签，所以 Lsynth 不含 |V − P|： 市价不是价值，价格只作诊断。区间传播与参数敏感度用 MC / 隐式微分； 离散与黑箱部分用策略搜索 / 贝叶斯优化，不假装有梯度。

后向角色与边界ACTOR / CRITIC
角色类比职责边界 / 约束
三专家actor只提本域内的参数修改建议 δ可比质量 / 折现参数 / 舆情；不改他人域，不写估值叙事
主审critic裁决 accept / clamp / reject只接受可行域 C 内的结果（命题 1：可行域保持）
shadow反事实对照参数不变，只留痕作为 apply 的基线对照；必须严格空操作
apply信赖域更新回写参数并重跑引擎保留 baseline；失败回滚；所有参数版本化
参数存储台账提案 → 审批 → 生效全链留痕可回放、可回滚；跨批可追溯
不是反向传播 · NOT BACKPROP 专家提议与主审裁决是协议，不是 prompt 堆叠，也不是梯度反传。更准确的说法是： 可微模块用隐式微分求参数敏感度；不可微模块用 actor-critic、策略搜索或贝叶斯优化； 约束用信赖域 / 投影。

起点不是从零开始：现有协议已有三专家 + 主审、severity caps、shadow / apply 与 baseline 回滚 （幅度上限示例：可比 5/8/10pp、舆情 5/10pp、WACC 0.4/1.0pp、永续 0.2/0.6pp，可作为信赖域上界的起点）。 V2 要做的是把它提升为独立的一层，并加上合成目标与校准指标。

04

神经网络类比的边界

ANALOGY BOUNDARY

一张表说清哪些类比成立、哪些需修正、哪些不成立。结论：把“神经网络”当架构隐喻成立； 把它当“有标签、可端到端训练、能反向传播”的系统不成立。 这是本分支的提法边界，也是对外表述必须守住的一条线。

神经网络类比对照ANALOGY AUDIT
NN 概念估值系统中的对应判定说明 / 边界
Layer / block估值模块（DCF、可比、舆情、RIM、rNPV、NAV…）成立每个模块是独立算子，有输入 / 输出 / 参数

可以写进论文 · KEEPVALID
  • 模块化、门控、残差、注意力、归一化、dropout、集成、池化都有明确语义，能形成真实的学术表达。
  • 评论家（专家 / 主审 / shadow / apply）可写成协议与信赖域算子，而不只是 prompt 工程。
  • 双场景共享模块带来 domain adaptation / transfer 研究问题。
必须克制 · RESTRAINBOUNDARY
  • 不要把“神经网络”当成有标签可训练的承诺。
  • 不要把“BP”当成真的反向传播；没有标签，也没有全图梯度。
  • 不要把“国家队操作”写成系统输出；只做估值温度 / 偏离诊断。
四条可写的命题（需严格假设）THEORY
  • 命题 1 · 可行域保持：若所有提议 δ ∈ C，主审只接受 C 内结果，则更新后参数仍在可行域，估值始终有定义。
  • 命题 2 · 池化单调性 / 有界性：线性池 / 对数池在正权重、正估值下保持上下界；专家乘积在对数空间等价于加权几何平均，分歧越大方差越大。
  • 命题 3 · Lipschitz 界：若各模块对输入 Lipschitz，则整图 Lipschitz 常数可由路径乘积给出，用于说明有界更新的稳定性。
  • 命题 4 · 校准误差：在合成基准上，区间覆盖误差随 MC 样本数 O(1/√n) 收敛；真实数据上只给经验校准，不给理论保证。

这些命题不需要“神经网络”假设，只需要算子性质与约束；严格形式化见 01 · 理论。

建议的提法 · POSITIONING VCG / MVN：一个类型化、可组合、可审计的估值计算图；前向由估值模块与门控 / 池化组成， 后向由带合成目标的智能体评论家做有界校准；同一组模块服务指数监控与 IPO 定价。
一句话：前向是“计算图”，后向是“评论家”，不是“神经网络训练”。

相关脉络（见 00 §5）：Neural Module Networks、Mixture-of-Experts、Hypernetworks、NAS / DARTS、 BMA / forecast combination、actor-critic / bilevel、LLM multi-agent debate、differentiable programming—— novelty 不是“首次把神经网络用于估值”，而是“类型化计算图 + 智能体评论家 + 双场景复用”的组合。

05

双场景：同一张图，两套域

TWO SCENARIOS

同一组估值模块，两个场景：monitoring（已上市监控）与 IPO（拟上市定价）。 共享的是模块与类型契约，隔离的是数据域、证据域与合规域；输出天然不同——一个给诊断，一个给区间与约束检查。 （场景细节见 04 · 两个用途）

SHARED · 6 共享模块财报编码 / 可比 / DCF / 池化 / 评论家 / 审计：接口与类型契约相同，差别只在配置、数据域与池化规则。
ISOLATED 数据域与证据域监控用公开行情、财报、公告、舆情；IPO 用公开数据 + 保密材料（招股书、问询回复、发行方案），独立缓存、最小必要授权、脱敏、留痕与归档。
CONTEXT 输出与合规监控给估值诊断与拟合点位；IPO 给估值区间与定价约束检查；两者都不输出单一决策，由人和机构按程序决策。
MONITORING · 已上市监控PUBLIC
  • 目标 · 指数与逐券的估值诊断：当前指数相对自身基本面中枢处在什么位置、偏离由谁贡献、判断有多不稳。
  • 输出 · 估值区间、指数拟合点位、偏离分布、行业 / 风格分解、时序稳定性；置信度与图级不确定性分开呈现。
  • 用途 · 内部研究、风控与讨论的“估值温度计”；不对外发布指数观点。
  • 边界 · 不是交易信号；不自动下单；不生成“国家队撤退 / 入场”或仓位 / 择时指令。表述限定在诊断词表：偏贵 / 偏便宜 / 接近中枢。
  • 状态 · 现有系统已有可跑通雏形（基线 d06a5ed）：五指数跑批、三专家 + 主审、shadow / apply、8 项机检。
公开数据 诊断 非交易信号
IPO · 拟上市定价RESTRICTED
  • 输入 · 监管通道的结构化财报、招股书要点、可比、行业参数、发行条款与募投；独立数据域、按项目授权、脱敏、全链留痕。
  • 输出 · 估值区间、方法分解、敏感性、可比证据链、IPO 定价约束检查；不输出单一“建议发行价”。
  • 决策 · 定价委员会、保荐机构与主承销商按监管规则与内部程序决策；系统只是研究参考，不替代保荐核查与信息披露。
  • 合规 · 公平披露、静默期、利益冲突、内幕信息隔离、模型风险、可解释与复核；所有输出标注“研究参考”。
  • 状态 · V3 目标形态；当前尚无保密数据通道、权限系统与审计登录，不能直接承接真实 IPO 项目。
监管通道 区间定价 不输出单一发行价
一句话 · TWO MODES 双场景不是“两个产品”，而是同一张前向图 + 两套域约束：共享模块降低维护成本， 隔离数据域与合规域守住边界；跨域适配只研究特征 / 先验迁移，不引入目标域标签。

风险与合规

RISK & COMPLIANCE

这个方向的工程门槛不是模型，而是审计与边界。以下三条红线在任何阶段都不放开； 无真值时，评估对象是机制、共识与一致性，而不是“猜得准不准”。

不自动交易NO AUTO-TRADE

输出是“估值温度 / 偏离诊断”，不是交易信号；不自动下单，不生成仓位、择时或“国家队撤退 / 入场”指令。

不自动定价NO AUTO-PRICE

IPO 只输出估值区间、方法分解、敏感性与证据链；不输出单一“建议发行价”，由定价委员会 / 保荐机构决策。

不把政策写成指令NO POLICY CALL

国家队 / 政策操作只作为外部情境讨论，不写成系统输出或操作建议；决策由人和机构按程序作出。

无真值评估 · 三件套（06 · 评估协议）
01 · 合成基准SYNTHETIC

已知 V★，注入财报错报、口径错误、可比缺失、路由错误等缺陷；测恢复误差、区间覆盖、路由准确、参数与图结构恢复。

02 · 人工盲评BLIND

隐藏 Agent 建议与点位；4–6 名内部评审独立评“证据 / 方向 / 幅度 / 置信”；两轮 Delphi + 仲裁；报 Krippendorff α。

03 · 内部一致性CONSISTENCY

同输入多 seed；股票 / 节点顺序、单位缩放、行业标签扰动；shadow 严格空操作；apply 回滚；8 项机检。

市场指标与发行结果只作外部效度与诊断，不作优化目标、不作训练标签；方向命中、跟踪误差、偏离分布不反向校正估值。

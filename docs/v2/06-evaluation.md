# 06 · 评估协议：没有真值时，怎么证明它可信

> 本系统没有 ground truth：市价不是价值，指数收盘不是答案，发行价也不是标签。  
> 因此评估的对象不是“猜得准不准”，而是三件事：**机制是否按设计工作**（合成基准）、**结论是否被人认可且一致**（人工盲评）、**同一输入是否稳定可复现**（内部一致性）。  
> 市场与发行结果只作外部效度与诊断，不作优化目标、不作训练标签。认识论立场见 [00](00-evaluation.md) §1–§2；执行顺序衔接实施计划（`05-implementation-plan.md`）。

## 1. 评估立场与对象

### 1.1 三个评估对象

- **图（机制）**：模块、门控、残差、注意力、池化是否按类型契约工作；换一种池化、关掉一个模块，结果是否可解释地变化。
- **评论家（校准）**：专家的建议是否被主审正确 accept/clamp/reject；置信度是否可信；建议是否过度反应或过于保守；人工是否采纳。
- **系统（一致性）**：同输入是否稳定、shadow 是否严格空操作、apply 失败是否可回滚、报告是否过 8 项机检、版本是否可重放。

### 1.2 三条原则

1. **三角验证而非单一排行榜。** 合成基准、盲评、一致性三类证据各自回答不同问题，任何一类都不能单独支撑“系统可信”。
2. **预注册。** 主指标、亚组、消融矩阵、停时规则在跑实验前锁定；不允许跑完再挑指标、挑样本。
3. **负结果同等报告。** 关掉某模块后更好、某池化更差、盲评 α 偏低，都是结果；只报成功案例等于自证。

### 1.3 不做什么

不用“准确率 X%”“跑赢指数”“预测点位”“覆盖率 100%”作为目标或卖点；不把指数收盘、发行价、首日涨幅当监督信号；不用同一批数据既调参又评估。

## 2. 无真值三件套

### 2.1 合成基准：已知 V*，测机制

用结构 DCF/RIM 在已知参数 `θ*` 下生成真实价值 `V*`，再构造带缺陷的输入，看系统能否按设计恢复、定位与降级。它测的是“机制是否按设计工作”，**不是“真实市场准不准”**。

- **生成**：合成 300 家企业，覆盖 general、金融、管线药企、多分部等路由；每家给出完整 `θ*`（WACC、永续增速、增长路径、方法权重）与干净特征。
- **注入错误**：财报错报（营收/净利 ±10%–30%）、口径错误（母公司 vs 合并）、可比缺失或错配、路由错误（金融误判为 general、growth 误判 decline）、单位错误（元/万元/亿元混用）、负 FCFF、pre-revenue、ST、新股、证据冲突。
- **规模**：首轮 300 家企业 × 2 种路由配置 × 2 档噪声 = 1,200 例，正式实验可扩到 3,000 例；每例重复 20–50 次以估计 LLM 采样与 MC 的随机性。
- **指标**：恢复误差 `|V̂−V*|/V*`（中位与 p90）；80%/90% 区间的实际覆盖率；路由准确率（主方法是否选对、不可用方法是否剔除）；参数恢复（WACC/g/权重的偏差）；图结构恢复（门控是否选中正确方法、残差是否被跳过、池化是否按预期切换）；对抗样本失败率。
- **预注册判据**：建议 90% 区间覆盖率 ≥85%、路由准确率 ≥90%、参数恢复偏差在预设带内；具体阈值在跑实验前锁定。注意覆盖率不是越高越好——过高说明区间过宽，需与宽度一起看。

除单券机制外，合成基准还要覆盖**图级机制**：人为构造“门控应选 A 方法却选了 B”“残差应跳过却放大”“池化应切换却未切换”的场景，检查系统是否按类型契约动作；对深图/宽图分别生成同分布样本，比较关节点前后的输出差异是否与设计语义一致。图级失败往往不表现为数值错误，而表现为“看起来合理但来源错误”，因此必须把诊断字段（门控权重、被跳过节点、池化选择）纳入判据，而不只看最终估值。

### 2.2 人工盲评：隐藏建议，测共识

盲评回答“证据是否撑得住结论”，不是测“谁猜得准”。

- **抽样**：从五指数分层抽 100–150 个券-周；分层维度为指数、行业、市值、引擎置信度、是否极端偏离。样本量不足时先做 20 例 pilot。
- **盲法**：隐藏 Agent 建议、隐藏拟合点位、隐藏评分者身份；只给证据包、估值区间、方法与参数说明。评分者不知道“系统想让他们看到什么”。
- **评分维度**：证据充分性（1–5）、方向（-2…+2，偏贵/中性/偏便宜）、幅度（1–5）、置信（0–1）、是否采纳（是/否/存疑），并留一栏自由理由。
- **流程**：4–6 名内部评审独立打分 → 两轮 Delphi（第一轮回传匿名分布与中位数，第二轮允许修订）→ 分歧项仲裁并记录理由。
- **两种设计**：绝对评分（对单个券-周按维度打分，成本低、适合大规模）与两两比较（同一券-周的两种配置/两个模型择优，噪声低、适合比较模型差异）。首轮用绝对评分建基线，比较版本差异时用两两比较；两种设计的分数不可混用。pilot 阶段重点检查评分表歧义、维度重叠，以及评审人是否理解“证据充分性”与“幅度”的区别。
- **统计**：Krippendorff α（序数或区间尺度）、评分者间一致率、Agent 置信与人工评分的校准曲线、两轮修订幅度。α 建议预注册阈值（如 ≥0.60），低于阈值时报告并降权使用，不强行解释。
- **合规**：仅内部员工、非敏感数据、匿名化；对外发表需单位审批与知情同意；盲评记录单独存档，不进入模型训练。

### 2.3 内部一致性：同输入，测稳定

- **seed**：同输入跑 5 个 seed，报告估值、建议、路由的方差；固定 seed 42 的两次运行必须逐位一致（现有 `stat_validation.py` 口径）。
- **排列**：股票顺序、可比顺序、图节点顺序、并行执行顺序打乱后，逐券输出应不变；顺序敏感处必须定位到具体节点。
- **单位**：元/万元/亿元缩放、百分比与小数互换后，估值与区间应按同一比例缩放，不得出现量纲错位。
- **行业扰动**：行业标签上下移动一级（申万二级→一级）、别名改写后，看路由、可比池与估值的稳定性；变化必须可解释。
- **shadow 空操作**：`shadow` 输出必须与无 Agent 基线在参数、估值、报告数值上完全一致，只多一条审计记录；不一致即协议缺陷。
- **apply 回滚**：注入重跑失败、参数越界、输出非正等故障，`baseline` 输入/输出必须逐字节恢复；参数台账回退到上一版本。
- **8 项机检**：结构、章节、数字一致、占位符、空表、单位、链接、免责声明的通过率与失败原因；机检通过不等于估值合理，但机检失败即不可交付。
- **图不变性**：增删可选模块不改变未受影响节点的输出；线性池可交换、对数池与专家乘积需显式记录顺序与相关性假设。

## 3. 下游任务：把评估落到两个场景

### 3.1 指数监控

- **偏离稳定性**：逐券 `e_i` 与指数加权偏离的周环比分布、自相关、符号翻转率；目标是“可解释的稳定”，不是“不动”。
- **跨期一致性**：同一券在相邻期的估值排名不宜大幅翻转；同一 as_of 下，上证50 ⊂ 上证180 ⊂ 上证综指的成分估值必须一致，点位差异应完全由权重解释。
- **异常捕获**：用预置异常（合成基准注入、人工标注）测召回率与误报率；真实数据上的异常（连续偏离、置信骤降、方法分歧）只作探索性标注，不当真值。
- **分解可加性**：行业/风格贡献之和应等于指数加权总偏离（允许舍入误差）；不满足说明权重、跳过券或分组口径有 bug。分解结果要能回答“偏离是普遍偏贵，还是少数极端券拉动”。
- **与真实指数的诊断相关性**：拟合偏离与指数未来收益的秩相关、行业偏差与行业收益的关系，**只作诊断**。报告必须同时给方向、显著性、样本量与置信区间；相关不显著或方向相反照实报告，不据此调参、不据此择时。

### 3.2 IPO 定价

- **与发行价的关系**：区间是否覆盖最终发行价、发行价落在区间内/外的原因（假设差异、可比选择、窗口因素）；**只作外部效度**，不把发行价当标签回灌模型。
- **与首日表现的关系**：区间位置与首日涨跌幅的秩相关、分组检验；样本小、选择偏差强（发行定价受规则与窗口指导影响），必须报告局限，不得写成“预测能力”。
- **区间覆盖**：在留出的 IPO 样本上，80%/90% 区间的实际覆盖率与宽度；覆盖率与宽度必须成对报告。
- **委员会采纳率**：定价委员会/保荐机构对区间、假设或约束检查的采纳/否决/存疑比例与理由分布；采纳率是人工认可指标，不是正确率。
- **定价约束检查**：对 `ipo_rules_checklist` 的规则项做命中/漏检分析；检查结果只说明“是否需进一步核查”，不构成合规结论。

## 4. 指标表

| # | 指标 | 定义 | 用途 | 方向 |
|---:|---|---|---|---|
| 1 | 覆盖率 | `ok / total`，按指数、按方法分层 | 系统可用性；必须与跳过原因一起报告 | 越高越好，但需解释 |
| 2 | 跳过率 | `skip / total`，按数据缺失、引擎失败、无有效估值分层 | 失败结构；静默跳过是缺陷 | 越低越好 |
| 3 | 离散度 / IQR | 逐券 `e_i` 或专家建议 `δ` 的中位、IQR、非零率 | 是否过度反应或过于保守 | 无绝对好坏，看稳定性与解释 |
| 4 | 置信校准 ECE | 分箱后“置信度 − 经验准确率”绝对值的加权和（合成基准/人工评分） | 置信度是否可信 | 越低越好 |
| 5 | Brier 分数 | 概率/区间校准的二次损失 | 与 ECE 互补，惩罚极端错误 | 越低越好 |
| 6 | 周环比稳定性 | 同券相邻期参数与估值的中位绝对变动、方向翻转率 | 参数是否抖动 | 越低越好，但不能以“不动”为目标 |
| 7 | 跨期一致性 | 相邻期估值排序 Spearman ρ；五指数交叉一致率 | 结论是否可跨期复现 | 越高越好 |
| 8 | 统计区间覆盖率 | 80%/90% 名义区间的实际覆盖比例（与系统覆盖率区分） | 不确定性是否诚实 | 接近名义水平；过高=过宽 |
| 9 | 区间宽度 | `W80 = (V⁺−V⁻)/V̂`（或 W90） | 不确定性的表达 | 覆盖约束下越窄越好 |
| 10 | 参数弹性 | `∂lnV/∂r`、`∂lnV/∂g` 等 ±1σ 扰动与 OLS 估计 | 解释 caps 与敏感性的必要性 | 解释用，不作优劣 |
| 11 | 模块/组件消融效应 | 留一法或关闭后的主指标差值与置信区间 | 每个模块是否有边际贡献 | 看 Δ 显著性，不预设正负 |
| 12 | 池化对比 | 线性/对数/专家乘积的估值差分布、极端券占比、区间宽度 | 合成语义是否改变结论 | 看差异与极端值，不预宣布最优 |
| 13 | 人工采纳率 | `adopted / (adopted + rejected)` | 人工认可与建议质量 | 越高越好，但防“全采纳”偏差 |
| 14 | 图深度/宽度与成本 | 节点数、最长路径、执行耗时、单节点失败隔离率 | 表达力与复杂度的权衡 | 表达力与成本同时报告 |

> 说明：方向列只是常规读法。覆盖与宽度、采纳与独立、稳定性与敏感度之间存在权衡，任何单一指标都不能作为系统的总排名；主指标必须在实验前预注册。

## 5. 消融

| 消融 | 设置 | 想回答的问题 | 主指标 |
|---|---|---|---|
| 关模块 | 逐一移除 DCF/可比/舆情/rNPV/NAV 等 | 每个模块的边际贡献是否为正是负 | 恢复误差、区间覆盖、消融 Δ |
| 关门控 | 固定等权、固定方法集，禁用行业/生命周期路由 | 门控带来的是信息还是噪声 | 路由准确率、离散度、校准 |
| 关残差 | 令残差缩放 `α_m = 0`，只用行业基准 | 残差项是否真的在建模“偏离中枢” | 估值偏差、极端券占比 |
| 关注意力 | 可比/证据等权，替代注意力权重 | 注意力是否优于等权基线 | 可比质量、区间校准 |
| 关 critic | `off / shadow / apply` 三档对照 | 评论家是否在“减错”而非“加噪” | 采纳率、离散度、周环比 |
| 池化 | 线性 / 对数 / 专家乘积 | 分歧惩罚与极端值处理是否改变结论 | 估值差、区间宽度、覆盖 |
| 图结构 | 深图/宽图/串行图；增删可选节点 | 层数越多是否越好；并行是否等价 | 主指标 + 成本；每次加层需单独证据 |
| seed | 5 个不同 seed、不同执行顺序 | 随机性对结论的影响幅度 | 方差分解、排名稳定性 |
| 阈值与 caps | 置信门槛 0.55/0.65/0.75；caps ×0.5/×1/×2 | 门槛与幅度上限如何影响采纳与校准 | 采纳率、建议离散度、校准 |

> 层数越多不等于越好：每增加一层或一个模块，都必须有单独的消融与证据，否则就是“估值领域的过参数化”（见 [00](00-evaluation.md) §2）。

## 6. 统计

- **券-周配对 bootstrap**：以券为聚类重采样（同一券的周度观测相关），按指数/行业分层，1,000–2,000 次；报告配对差值的中位数、95% 置信区间与效应量（如 Cliff's δ 或标准化中位差）。
- **混合效应模型**：`metric ~ treatment + (1 | index) + (1 | industry) + (1 | lifecycle)`，处理重复测量与不平衡样本；必要时加入时间随机斜率，区分“处理效应”与“时间趋势”。
- **多重比较**：消融矩阵 × 指标构成检验族，用 BH-FDR 控制错误发现率，报告 q 值；同时保留未校正 p 值供读者判断，不隐藏。
- **预注册**：主指标、次指标、亚组、停时规则、排除规则（跳过券、极端值 winsorize）与统计计划在跑实验前写死；变更需留痕并说明原因。
- **负结果**：报告失败消融、方向相反的效应、跨零的置信区间与不显著的主指标；不以“样本不够”掩盖，明确列为局限。

## 7. 效度：结论能推广到哪

评估要区分五类效度，报告时分别声明：

- **内部效度**：shadow 反事实、随机 seed、回滚测试与盲评保证“看到的变化确实来自处理”；威胁是 LLM 随机性与数据漂移。
- **外部效度**：五指数、单一市场、有限时间窗口；合成基准的生态效度有限；IPO 样本更小、选择偏差更强。跨市场/跨期复现前，不把结论外推。
- **构念效度**：离散度、校准、稳定性、采纳率是否真的代表“估值质量”？需要质性访谈、案例复盘与专家判断补充，不能只靠指标。
- **统计结论效度**：样本量、聚类相关、多重比较；券-周不独立，必须用聚类 bootstrap 与混合效应。
- **可复现性**：代码、数据 as_of、模型与提示词版本、随机种子、预注册文档齐全，第三方能在同一口径下重跑。

## 8. 反循环

| 风险来源 | 具体表现 | 缓解 |
|---|---|---|
| 证据同源 | 专家证据与引擎输入来自同一数据源，主审看到的只是同一事实的不同叙述 | 引入异构数据（公告、审计报告、行业协会、第三方数据）、外部证据核对、盲评 |
| 模型同源 | 三专家、主审、报告生成使用同一模型与同一提示词家族 | 用不同厂商/不同版本模型做第二评审；保留规则基线；记录模型 id 与提示词版本 |
| 评估者=开发者 | 内部盲评者也是系统开发者，倾向认可自己的设计 | 外部评审、双人独立评分、预注册、盲法、公开负结果 |
| 目标同源 | 同一批数据既调参又评估，指标自然变好 | 时间切分（前段调参、后段评估）、留出指数/行业、shadow 反事实 |
| 选择偏差 | 只展示表现好的指数、行业或案例 | 全样本报告、按指数分层、失败案例单列 |

`shadow` 与 `apply` 的区分是因果识别的基础：`shadow` 是“没有 Agent”的反事实，`apply` 是“Agent 实际造成什么”的处理组；没有这两条，评论家的效果无法与数据波动分开。

## 9. 不能写什么

- 不写“准确率 X%”“预测精度 X%”——没有真值，任何准确率都必须说明分母、口径与对照，且不能作为卖点。
- 不写“跑赢指数”“超额收益”“跟踪误差优于基准”——这不是系统的优化目标。
- 不写“预测点位”“预测发行价”“命中率”——系统只给诊断与区间。
- 不写“覆盖率 100%”“所有券都可估值”——跳过与失败必须如实报告。
- 不写“多 Agent 一定更准”“层数越多越好”“专家乘积必然优于线性池”——都需要消融证据。
- 不把示例案例、合成基准、诊断相关性写成实证结论；不把合规检查写成法律意见。

---

## 10. 执行顺序与交付

1. **M0 先锁基线**：冻结 `examples`、170 个冒烟用例、8 项机检与代码版本，作为所有比较的分母。
2. **V1 后跑合成基准**：先 1,200 例，预注册阈值，报告恢复误差、覆盖、路由与图结构恢复。
3. **V2 后跑一致性**：seed/排列/单位/行业扰动、shadow 空操作、apply 回滚、8 项机检。
4. **V2 后做盲评**：先 20 例 pilot 校准评分表，再扩到 100–150 券-周，报告 α 与校准。
5. **V3 后做下游**：监控看偏离稳定性与跨期一致；IPO 看区间覆盖、委员会采纳率与外部效度，始终标注“只诊断”。
6. **写作与评审**：按 P3 协议编号预注册与实验；所有结论带点估计、区间、样本量、覆盖率与失败率；负结果单列。

评估结论的统一格式是“**点估计 + 区间 + 样本量 + 覆盖/失败率 + 局限**”，缺一项即视为未完成。

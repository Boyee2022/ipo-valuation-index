# 04 · 两个用途：已上市监控与 IPO 定价 Demo

> **2026-11-28 demo 口径**（以 [08](08-demo-first-revision.md) 为准）：只用**公开/构造数据**；**不做鉴权、不做脱敏、不做数据域隔离、不做合规认证**。  
> 两个用途共享同一组估值模块，`mode=monitoring|ipo` 只是行为/缓存口径开关，不是安全边界。  
> 目标：先把两条链路跑通、把论文写出来；生产化（权限、保密、合规）另议，不列入本轮验收。

---

## 1. 共同前提

- 数据：公开行情/财报/公告/舆情；IPO 用公开或构造的公司样例。
- 输出：估值区间/点位 + 方法分解 + 证据链 + trace；不输出交易指令，不输出单一发行价。
- 模块：DCF、DCM、可比、舆情、RIM/DDM、行业兜底、门控、三池、指数合成。
- 可复现：同 `as_of + 参数包 + 模块版本`，结果稳定；LLM 用缓存 + temperature=0 + 3 次一致性检查。
- 边界：demo 结果不构成投资建议，不可作为发行定价依据。

---

## 2. 场景 A：已上市企业动态估值监控

### 2.1 目标

- 逐券估值 → 指数拟合点位 → 偏离分布 → 行业/风格分解 → 时序稳定性。
- 用途：内部研究、风控、指数编制讨论的“估值温度计”。

### 2.2 输入/输出

**输入**：指数（上证50/180、科创50、沪深300、上证综指）、as_of、公开行情/财报/公告/舆情。

**输出**：

- 逐券：估值中枢、区间、置信度、方法分解、证据、trace；
- 指数：拟合点位、三情景点位、与收盘的偏离（诊断）、贡献分解；
- 诊断：偏贵/偏便宜、结构分化、异常券、置信度分布；
- 报告：HTML + 逐券下钻。

### 2.3 语言边界

统一使用诊断词表：偏贵、偏便宜、接近中枢、不确定性高、证据不足、结构分化。  
禁用词表：买入、卖出、加仓、减仓、撤退、入场、平仓、抄底、逃顶。  
**“国家队/平准基金”不进入产品输出**；政策决策由有权机构按程序作出，系统只提供估值诊断。

### 2.4 工作流

```text
选指数/日期 → A 数据收集 → B 模块加载 → C 批量估值 → D 池化/指数拟合 → 报告/下钻
```

### 2.5 当前状态

已有五指数跑批、逐券估值、拟合点位、shadow/apply 评审与 8 项机检；本轮按 A–D 重构执行层。

## 3. 场景 B：拟上市 IPO 定价 Demo

### 3.1 目标

- 输入结构化公司信息（公开/构造）：财报、业务、可比、行业、发行条款（可选）。
- 输出估值区间、方法分解、敏感性、可比证据链、定价约束检查。
- 用途：演示“同一组模块如何服务单公司定价”，以及监管需求变化时如何换模块/口径。

### 3.2 明确不做

- 不接真实保密材料；不做权限、脱敏、项目隔离、访问审计。
- 不输出单一“建议发行价”；不替代定价委员会/保荐机构。
- 不做合规结论、法律意见、静默期/利益冲突审查。

### 3.3 输入/输出

**输入**：公司代码/名称（或构造样例）、as_of、公开财报、可比池、行业、发行条款（可选）。

**输出**：

- 估值区间（悲观/基准/乐观）、中枢；
- 方法分解（DCF/DCM/可比/舆情/RIM…）、权重、敏感性；
- 可比证据链、数据来源、假设；
- 定价约束检查（发行市盈率/市销率 vs 可比、募资/市值、摊薄等），标“通过/需关注/不满足”；
- 报告：HTML。

### 3.4 工作流

```text
公司样例/公开材料 → A 数据收集 → B 模块加载（IPO 子图） → C 单公司批量 → D 区间/敏感性/报告
```

### 3.5 当前状态

技能包已有单公司估值方法与报告章节；本轮用公开/构造样例做 demo，不接真实项目。

## 4. 两个场景的共享与差异

| 维度 | A 已上市监控 | B IPO 定价 Demo |
|---|---|---|
| 数据 | 公开行情/财报/公告/舆情 | 公开/构造公司样例 |
| 模块 | DCF/DCM/可比/舆情/RIM/行业兜底/池化 | 同上；可加 rNPV/NAV/SOTP |
| 输出 | 指数点位、偏离、诊断 | 估值区间、方法分解、定价约束 |
| 行为开关 | `mode=monitoring` | `mode=ipo` |
| 安全/合规 | **不做** | **不做**（生产化另议） |
| 当前状态 | 已有雏形，重构执行层 | Demo 目标，V4 交付 |

**共享**：同一套 `ModuleSpec`、池化、报告、trace；换模块/口径只改图与参数包。  
**差异**：方法集、输出形态、数据样例；不是安全域。

---

## 5. 监管需求变化的响应方式

这是模块化最重要的工程价值：

1. 新口径 → 新增/替换一个 `val.*` 模块，注册到图；
2. 新披露字段 → 在 A 段加列 + mask，不改 C/D；
3. 新池化/权重 → 改 `pool` 参数包，不改模块；
4. 新报告要求 → 在 D 段加报告模板，不改估值；
5. 回滚 → 固定 `module_version + params_hash`。

验收标准：**换一个模块/口径，只改图与参数包，不改数据段与批处理段**。

## 6. 阶段与边界

- V0 参照/骨架 → V1 A 数据 → V2 B 模型加载 → V3 C 批处理/断点 → V4 D 指数拟合/IPO demo。
- V5 评论家/校准为研究线。
- 本轮不做：鉴权、脱敏、数据域隔离、真实保密材料、合规认证、自动交易/自动定价。

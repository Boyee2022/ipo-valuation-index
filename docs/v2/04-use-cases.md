# 04 · 两个用途：已上市监控与 IPO 定价

> 这张图给谁用、怎么用、用到哪里必须停，是本章要回答的问题。  
> 已上市监控输出**估值诊断**，拟上市 IPO 输出**估值区间**；两者共用同一组估值模块，但不共用数据域、方法集与合规域。  
> 边界与 [00 · 评估](00-evaluation.md) §8 一致；评估协议见 [06](06-evaluation.md)，合规与治理见 [07](07-compliance.md)。

## 1. 两个场景的共同前提

VCG 的前向是“数据 → 图 → 池化 → 指数/区间合成”，后向是智能体评论家（专家提议、主审裁决、shadow/apply）。要让同一组模块服务两个场景，有三条不能破的前提：

1. **市价与发行价都不是答案。** 已上市场景里，真实指数收盘只用于诊断；IPO 场景里，发行价与首日表现只用于外部效度检验。二者都不是训练标签，也不进入优化目标。
2. **不输出单一决策。** 监控不输出买卖、仓位、择时与政策指令；IPO 不输出“建议发行价”。系统只提供证据、区间与约束检查，决策由有权的机构按程序作出。
3. **每个结论可回溯。** 每个数字都带数据来源、参数版本、证据链与置信度；报告机检与人工复核属于交付物的一部分，不是可选项。

> 状态说明：场景 A 在现有系统（基线 `d06a5ed`）上已有可跑通的雏形——五指数跑批、逐券估值、拟合点位、三专家加主审的 `shadow/apply` 评审、8 项机检；场景 B 是 V3 的目标形态，当前只有技能包的估值方法与报告章节作为基础，**尚无保密数据通道、权限系统与审计登录**，不能直接承接真实 IPO 项目。

## 2. 场景 A：已上市企业动态估值监控

### 2.1 目标

监控要回答的不是“该买还是该卖”，而是“当前指数相对自身基本面中枢处在什么位置、偏离由谁贡献、这个判断有多不稳”。目标拆成五项：

- **逐券估值**：给每只成分券一个中枢、一个区间、一个置信度，以及方法分解与证据链。中枢不是“合理股价”，而是现有假设下模型能给出的条件估值。
- **指数拟合点位**：按指数权重把逐券估值合成为点位。当前主口径为 `V_idx = P_idx × Σ w_i (V_i / P_i) / Σ w_i`，价格加权口径只作对照；跳过券不计入分子分母。三情景点位由逐券区间按同一权重合成。
- **偏离分布**：逐券 `e_i = V_i / P_i − 1` 的截面分布、加权均值、分位数，以及估值/价 ≥5× 或 ≤0.2× 的极端券；极端券只标识并给出贡献 pp，不反向修改估值。
- **行业与风格分解**：按申万行业、市值、估值风格分组，看指数偏离中各组的贡献；区分“行业整体偏贵”与“个别券把点位拉偏”。
- **时序稳定性**：同一券/同一指数的估值与参数逐周是否抖动、排名是否翻转、异常券是持续存在还是一闪而过。

覆盖口径沿用现有五指数：上证50、上证180、科创50、沪深300 与上证综指（沪市 A 股全市场，约 2,201 只，总市值权重，剔除 ST/*ST 与未满计入期新股）。

### 2.2 频率、数据时点与诊断口径

- **频率**：日频用于异常捕获与盘中讨论，周频用于正式报告与人工复核（每周最后一个交易日）。日频只做诊断，不因单日噪声调整参数。
- **数据时点**：每批必须有 manifest，记录成分表 as_of、财务报告期、行情 as_of、权重口径（官方权重或按市值归一）与代码版本；不同 as_of 的资源不得拼接。当前估值日期只是“参考”，批跑实际使用成分数据时点，属于“准 PIT”，报告与论文必须披露这一限制；接入真正 PIT 前不得声称回测可复现。
- **与真实收盘的关系**：真实指数收盘只用于画对照线、算偏离与诊断相关性。系统不据此反向校正估值，不把“贴近收盘”作为优化目标，也不优化跟踪误差；估值/价 ≥5× 的极端偏离只做标注与贡献分解，不改变权重或点位。

### 2.3 输出

- **估值温度计**：指数层的一个诊断读数——“相对基本面偏贵 / 偏便宜 / 接近中枢”，附区间、置信度、覆盖率与样本结构。读数必须带不确定性，不允许只给一个方向词。
- **偏离结构**：截面分布图、行业/风格贡献瀑布图、极端券清单及其对点位偏离的贡献 pp。
- **异常券**：偏离异常、方法分歧异常、置信度骤降、证据缺失四类，分原因列示；异常不等于错误，只表示“需要人看”。
- **置信度**：引擎置信度、图级不确定性（门控是否稳定、池化是否敏感、评论家是否分歧）分开呈现，不合并成一个分数。
- **证据链**：每券的方法树、参数溯源、证据条目、敏感性与区间；报告侧以 11 段结构 + 8 项机检保证可复核。
- **明确不输出**：买卖建议、目标价、仓位、择时信号、政策操作指令。

周报采用固定结构：本期温度计与区间 → 偏离结构与行业/风格贡献 → 异常券清单与原因 → 证据缺口与置信度变化 → 人工复核意见与“是否进入内部简报”的结论。结构固定是为了让跨期可比、让读者先看诊断再看证据，而不是每期换一种叙事。

### 2.4 使用边界

监控结果只供**内部研究、风控与讨论**。它可以进入研究简报、内部评审会和风险提示，但不能作为对外发布的指数观点，也不能用于指数产品跟踪或业绩宣传。

政策讨论中的表述必须收在“诊断”这一层：系统可以写“当前指数相对基本面偏贵/偏便宜”“偏离主要集中在某行业”“置信度偏低、证据不足”，**不能写“国家队撤退/入场/平仓”“建议减仓/增持”“平准基金应如何操作”这类自动指令**。政策决策由有权机构按既定程序、结合更多信息作出，模型输出只是参考项之一，不构成建议，也不代表任何机构立场。

为避免语言漂移，报告与页面统一使用诊断词表：偏贵、偏便宜、接近中枢、不确定性高、证据不足、结构分化；禁用词表：买入、卖出、加仓、减仓、撤退、入场、平仓、抄底、逃顶。评审与合规抽查按词表检查，命中即退回修改。

### 2.5 工作流

数据 → 图 → 池化 → 指数合成 → 评论家 → 报告 → 人工复核。评论家只做参数评审（`shadow` 留痕、`apply` 有界回写并保留 baseline），不改变估值叙事；人工复核负责解释异常、决定是否采纳建议、判断本期结论能否进入内部简报。图契约（节点、端口、门控、数据域）以 [graphs/monitoring.yaml](graphs/monitoring.yaml) 为准，流程图只是它的可视化摘要。

```mermaid
flowchart LR
  A[数据层<br/>公开行情 / 财报 / 成分权重 / 舆情] --> B[类型化估值图<br/>财报编码 → 方法核<br/>门控 / 残差 / 注意力]
  B --> C[池化<br/>线性 / 对数 / 专家乘积]
  C --> D[指数合成<br/>拟合点位 / 三情景 / 偏离分解]
  D --> E[评论家<br/>三专家 + 主审<br/>shadow / apply]
  E --> F[报告<br/>温度计 / 偏离结构 / 异常券 / 证据链]
  F --> G[人工复核<br/>研究 / 风控 / 内部讨论]
  E -. 有界参数回写（需审批） .-> B
```

## 3. 场景 B：拟上市 IPO 定价（监管通道）

### 3.1 输入与数据域

IPO 场景的输入分六类：**结构化财报**（审计报告与招股书财务章节归一化后的三表与关键指标）、**招股书要点**（业务模式、行业与竞争、风险因素、募投项目）、**可比**（上市同业与近期同行业 IPO，含长名单、剔除台账与信息截点）、**行业参数**（行业 β、WACC 区间、倍数中枢、生命周期先验）、**发行条款**（发行股数、老股转让、募资额、发行后总股本与市值、锁定期、超额配售安排）与**募投**（项目投向、投资额、达产节奏、对收入与利润的增量）。

这些材料大多属于**保密材料**：申报稿、问询回复、未披露财务数据、发行方案都不能进入公开数据域。工程上必须满足：独立数据域与独立缓存、按项目授权的最小必要访问、对外字段脱敏、全链路留痕、任务结束后的归档或销毁；**材料只能用于本项目估值研究，不得挪作他用、不得进入公开模型训练、不得跨项目复用**。数据治理细节见 [07](07-compliance.md) §2。

材料结构化的同时做四类质量检查：三表勾稽（利润表—现金流量表—资产负债表的一致性）、口径一致（申报稿与审计报告、母公司口径与合并口径）、信息截点（财务期末与可比信息截止日不得晚于基准日）、缺失分级（关键字段缺失降置信度或列入未决问题，不静默填充）。检查不通过不阻断整条链，但必须在报告中显性标注，且不得用默认值掩盖。

### 3.2 输出

- **估值区间**：`[V_low, V_high]`，按方法分解（DCF、可比、rNPV、NAV、SOTP 等）给出各自区间与权重，并说明区间宽度由方法分歧、数据质量还是情景假设主导。
- **敏感性**：WACC/Ke、永续增速、增长率、可比倍数、在研管线成功率（rNPV 的 PoS）等关键假设的弹性，以及区间端点对应的假设组合。
- **可比证据链**：长名单与最终样本、剔除理由枚举、覆盖率、规模倍数、会计可比性、信息截点，保证“为什么是这几家”可回答。
- **IPO 定价约束检查**：按技能包 `assets/ipo_rules_checklist.md` 与交易所规则，检查发行市盈率/市销率与可比的关系、发行后市值与募资匹配、募投与估值增量的对应、摊薄影响、板块定位与未盈利企业的特殊披露要求。检查输出“通过/需关注/不满足”与依据，**不是合规结论，更不是法律意见**。
- **置信度与未决问题清单**：哪些假设需要发行人补充、哪些可比缺失、哪些条款会显著改变区间。

最重要的一条：**输出区间，不输出单一“建议发行价”**。区间的作用是给定价委员会一个可讨论的锚与边界，而不是替委员会做决定。

### 3.3 决策与责任

定价决策由**定价委员会、保荐机构与主承销商**按监管规则和内部程序作出；系统只做研究参考，不替代保荐核查、不替代询价过程、不替代信息披露，也不承担定价责任。系统给出的区间、约束检查与证据链，是委员会讨论的输入；最终价格、发行方案与风险揭示由人和机构签字负责。

### 3.4 工作流

材料结构化 → 质量/完整性检查 → 图（IPO 子图）→ 区间 → 评论家 → 合规检查 → 报告。与监控场景相比，多了“保密材料进域前的授权与脱敏”“质量/完整性检查”“IPO 定价约束检查”三个卡点，且评论家不接触与本次发行无关的其他项目数据。IPO 子图契约见 [graphs/ipo.yaml](graphs/ipo.yaml)，其数据域按 deal 级隔离。

```mermaid
flowchart LR
  A[招股书 / 审计报告 / 问询回复<br/>保密材料] --> B[材料结构化<br/>字段 + 来源 + as_of]
  B --> C[质量与完整性检查<br/>勾稽 / 截点 / 缺失 / 口径]
  C --> D[IPO 子图<br/>DCF / 可比 / rNPV / NAV / SOTP]
  D --> E[区间合成<br/>方法分解 + 敏感性 + 证据链]
  E --> F[评论家<br/>证据门槛 + 参数评审]
  F --> G[合规检查<br/>定价约束 / 公平披露 / 静默期]
  G --> H[研究报告<br/>估值区间 ≠ 发行价]
  H --> I[定价委员会 / 保荐机构 / 主承销商]
```

## 4. 两个场景的共享与差异

### 4.1 共享模块

两个场景共享六个模块，接口与类型契约相同，差别只在配置、数据域与池化规则：

| 共享模块 | 职责 | 两场景的差异点 |
|---|---|---|
| 财报编码 | 三表归一、口径对齐、单位与披露档处理 | IPO 多一层申报稿/上会稿版本与信息截点 |
| 可比 | 长名单、筛选、剔除台账、注意力加权 | IPO 可比更稀、更依赖近期发行样本 |
| DCF | 显式期、终值、增长路径与折现参数 | IPO 更依赖情景与敏感性，终值占比需更严格限制 |
| 池化 | 线性 / 对数 / 专家乘积，区间传播 | IPO 更需要区间与专家乘积，监控以线性为基线 |
| 评论家 | 三专家 + 主审、证据门槛、caps、shadow/apply | IPO 评论家审的是定价假设，不是交易时点 |
| 审计 | trace、版本冻结、机检、回滚、留痕 | IPO 需项目级隔离与更细的访问审计 |

### 4.2 对比表

| 维度 | A · 已上市监控 | B · 拟上市 IPO 定价 |
|---|---|---|
| 目标 | 指数与逐券的估值诊断 | 发行区间与定价约束检查 |
| 数据域 | 公开数据（行情、财报、公告、舆情） | 公开数据 + 保密材料（招股书、问询回复、发行方案） |
| 数据时点 | 日/周，准 PIT，manifest 记录 as_of | 申报稿/上会稿/注册稿版本，信息截点严格 |
| 方法集 | DCF、可比、舆情、RIM/DDM，少数 rNPV/NAV | 在监控方法集上增加 rNPV、NAV、SOTP、募投与摊薄分析 |
| 主要输出 | 拟合点位、偏离分布、行业/风格分解、温度计 | 估值区间、方法分解、敏感性、可比证据链、约束检查 |
| 决策主体 | 内部研究/风控/讨论；政策由有权机构按程序决定 | 定价委员会、保荐机构、主承销商 |
| 合规重点 | 不构成投资建议、不输出交易/政策指令 | 保密材料隔离、公平披露、静默期、利益冲突 |
| 评估重点 | 偏离稳定性、跨期一致性、异常捕获 | 区间覆盖、委员会采纳率、外部效度（只诊断） |
| 当前状态 | 已有可跑通雏形（`d06a5ed`） | V3 目标形态，尚无保密通道与权限系统 |

### 4.3 可迁移性与 domain adaptation 研究问题

两个场景共享模块，使“跨域迁移”成为可研究的问题，而不是工程口号。V4 阶段值得回答四个问题：

1. **模块可迁移性**：同一 DCF/可比模块在两域的输入分布差异有多大？参数先验（行业 β、永续增速、倍数中枢）从上市公司迁移到拟上市公司时，区间校准是否变差？迁移的是先验、特征还是结构，必须分开报告。
2. **门控与路由迁移**：IPO 样本里亏损、pre-revenue、新股、单一客户、红筹/VIE 结构更常见，监控场景的生命周期判别与 Layer 0 路由可能系统性失效；需要测“迁移后路由准确率下降多少、由哪些行业承担”。
3. **评论家迁移**：保密材料的证据密度高但样本少，专家证据门槛与参数 caps 是否需要重标定？评论家在两域的建议分布、采纳率与校准是否同构？
4. **评估迁移**：合成基准与盲评协议能否跨域复用？IPO 的发行价与首日表现只能作外部效度，不能当训练标签；监控的价格诊断相关性也不能当迁移目标。域适配层只做特征与先验迁移，不引入目标域标签；同时要报告**负迁移**（迁移后更差）而不是只报成功案例。

### 4.4 场景选择判据

判断一段需求属于 A 还是 B，看三点：数据是否可以公开、结论是否落到单一发行主体、输出是否需要发行条款与定价区间。三者有其一触及保密材料或发行决策，就必须走 B 的隔离与合规流程，不能借 A 的公开数据通道绕过。反过来，A 场景不得引用 B 的任何保密结论，包括“某公司估值区间”这类间接信息。

## 5. 不做什么

- 不输出交易指令、仓位建议、择时信号，不写“国家队撤退/入场/平仓”，不把估值诊断映射为政策操作。
- 不为 IPO 输出单一“建议发行价”，不替定价委员会、保荐机构或主承销商决策，不替代保荐核查与信息披露。
- 不预测指数点位，不承诺准确率，不声称跑赢指数，不对外发布指数观点。
- 不把保密材料带出数据域，不把 IPO 数据用于其他项目或模型训练。
- 不把合成基准、示例案例或诊断相关性包装成实证结果；示例只作演示，标注“非回测”。

## 6. 与路线图的衔接

两个场景不是同时交付，而是分阶段开放能力：

- **V0–V1**：先用监控场景把“包住现有引擎”的图执行器跑通，验收拟合点位、偏离诊断与数值零回归；IPO 场景只做接口预留。
- **V2**：评论家成为独立层，先跑 `shadow`，再小范围 `apply`；监控场景积累采纳率与周环比数据。

- **V4**：在 V3 稳定后做跨域迁移研究，只做特征/先验迁移，不引入目标域标签。

每个阶段都要在文档里标明“已实现 / 论文提议 / 未上线”，避免把目标形态写成现有能力；评估与合规的验收见 [06](06-evaluation.md) 与 [07](07-compliance.md)。

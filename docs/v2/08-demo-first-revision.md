## 2. 逐条分析

### 2.1 Demo 优先：把“生产合规”从本轮拿掉

你的判断是对的：demo 阶段最大的成本不是模型，而是鉴权、数据隔离、脱敏、合规评审。这些在 demo 里**不产生学术价值**，只会拖慢“先做出来”。

本轮明确：

- 数据只用公开数据（东财、腾讯、公开披露）与构造样例；**不接真实保密材料**。
- 3089 服务保持现状（无鉴权、CORS 放行），只在可信内网 demo；不为此加登录/权限/租户。
- 不做“脱敏/匿名化/数据域隔离”的工程；IPO 场景只用公开或自造公司样例演示“输入结构化财报 → 估值区间”。
- 合规文档改成“未来生产化提示”，不作为本轮验收项。

**风险提示（只一句）**：demo 结果不可对外作为发行定价依据；论文/对外材料标注“研究方法，不构成投资建议”。不再展开合规清单。

### 2.2 完全重构：技能只做参照，不做运行时依赖

“只参考当前技能”意味着：

- 现有技能包的**公式、参数、Layer 0 规则、六阶段、报告结构**是参照物；
- 但新系统的模块、数据契约、执行器、参数存储**全部重写**，不把 `valuation_engine.py` 作为黑盒长期调用；
- 现有技能只用于**回归 oracle**：同一输入下，新模块输出与旧引擎的差异要可解释（允许有意变更，但必须记录）。

因此 V0 不再叫“包 LegacyModule”，而是：

> **V0 参照提取**：从技能包提取公式/参数/样例，生成 golden fixtures；新包 `packages/valuation_net/` 从零搭骨架。

旧引擎可以临时作为测试 oracle，但不进入新系统运行时。这样避免“重构”变成“包一层”。

### 2.3 神经网络只是类比：借效果，不借训练承诺

你说得对：神经网络最厉害的是**可训练拟合、迭代、鲁棒**；我们这套偏**审计**。正确的写法是：

| 神经网络的效果 | 我们的对应 | 是否承诺 |
|---|---|---|
| 可组合的层 | 类型化模块图（DCF、DCM、可比、舆情、RIM…） | ✅ 工程实现 |
| 可训练拟合 | 用合成基准/盲评校准门控与池化参数（离线、受约束） | ⚠️ 研究项，不是端到端训练 |
| 迭代 | 批间评论家（shadow/apply/回滚） | ✅ 工程实现 |
| 鲁棒性 | 集成、dropout、区间、消融、异常隔离 | ✅ 工程实现 |
| 端到端 BP | 无标签、离散模块、硬约束 | ❌ 不做，也不声称 |

**真正的贡献**不是“神经网络”，而是：

> 在监管需求多变的环境里，把估值拆成**可插拔、可解释、可审计的模块**；换模型/换口径只改图与参数，不改整条 pipeline。这比“再训一个黑箱”更符合估值定价的审计属性。

论文表述建议：标题/摘要可用“neural-inspired / modular valuation network”，方法章节明确“we do not train end-to-end; we compose auditable operators”。不要写“BP”。

### 2.4 四段式流水线：A 数据 → B 模型加载 → C 批处理/断点 → D 指数拟合

这是本轮最重要的工程修订。原 `02-architecture` 的“七层”偏概念，现改为**四段执行架构**：

```text
A. 数据资料收集
   源适配器（东财/腾讯/公开披露）→ 标准化 → 宽表/列式缓存 → manifest（as_of、来源、缺失掩码）
        │
B. 模型层加载
   模块注册表 → 依赖图 → 参数包 → 常驻 worker 池 → 预热/健康检查
        │
C. 批处理 + 断点恢复
   按模块/层分批（chunk）→ 向量化计算 → 每 chunk 原子落盘 → manifest 记录完成/失败 → 可恢复
        │
D. 指数选择与拟合
   选指数/权重 → 池化 → 拟合点位 → 三情景 → 诊断/报告
```

关键设计：

- **模块常驻**：B 段一次性加载模块与参数，C 段批量跑完再退出；避免每券重复 import/初始化。
- **尽量向量化**：基础层（财务、DCF、可比、DCM、池化）按矩阵/列式批处理；非基础层（舆情、LLM 评审）逐券/小批并发。
- **断点恢复**：manifest 记录 `batch_id + as_of + module_version + params_hash + chunk_id + status`；已完成 chunk 跳过，失败 chunk 重跑；输出原子写。
- **失败隔离**：单券/单模块失败只写 mask/错误，不阻断整批；D 段按剩余权重再归一。
- **可复现**：同 `as_of + 参数包 + 模块版本` 下，C 段输出稳定；LLM 用缓存与确定性解码。
- **模块加载**：每个模块有 `ModuleSpec`（类型、输入/输出、参数 schema、版本、健康检查）；加载失败只禁用该模块，不拖垮全图。

### 2.5 DCF / DCM 及所有模型都作为模块

模块目录新增：

- `val.dcf`：FCFF/FCFE 两阶段/三阶段 DCF。
- `val.dcm`：**折现/资本化模型族（DCM）**。按你的口径先作为独立插槽保留；具体公式（股利资本化、现金流资本化、或 DCF 的变体）在实现前确认，不与 DCF 合并，便于监管按需替换。
- `val.ddm`、`val.rim`、`val.rnav`/`val.nav`、`val.rnpv`、`val.sotp`、`val.comparable`、`val.sentiment`、`val.industry_fallback`。
- 门控/残差/注意力/池化/区间/指数合成。
- 评论家：三专家、主审、shadow/apply、参数台账。

模块化的验收标准不是“代码放在一个文件里”，而是：**换一个模块/口径，只改图与参数包，不改数据段和批处理段**。

### 2.6 LLM 无 seed：用“同结论”而不是“逐位一致”

你说得对，seed 不是重点；目标是同输入下结论稳定。做法：

1. `temperature=0`、`top_p=1`、固定 model/prompt/参数版本；
2. **响应缓存**：key = hash(model, prompt, evidence, params_version)；命中直接复用；
3. **3 次一致性检查**：缓存未命中时最多 3 次采样，按多数结论/参数中位数；不一致则标记 `unstable` 并走规则兜底；
4. 记录 model id、prompt hash、温度、缓存 key、采样次数，不要求 seed；
5. 论文报告“结论稳定率/参数方差”，不声称逐位可复现。

这比追求 seed 更符合“审计 + 同结论”的目标，也避免 API 不支持 seed 时卡住。

## 3. 修订后的路线（与 05 对齐）

| 阶段 | 目标 | 主要工作 | 验收 |
|---|---|---|---|
| **V0 参照与骨架**（2 周） | 完全重构的起点 | 提取技能公式/参数/样例为 golden fixtures；建 `packages/valuation_net/` 骨架；定义 ModuleSpec/Batch/ModuleOutput/GraphSpec | 旧技能样例可被新骨架读取；差异清单 |
| **V1 数据段 A**（3 周） | 数据收集/标准化/缓存 | 源适配器、宽表、manifest、缺失掩码；公开数据 demo | 同一 as_of 数据可复现；缺数据可解释 |
| **V2 模型加载 B**（3 周） | 模块注册/加载/常驻 | DCF、DCM、可比、舆情、RIM、门控、池化；worker 池；健康检查 | 模块可插拔；换模块不改 A/C/D |
| **V3 批处理 C**（4 周） | 向量化 + 断点恢复 | chunk 批处理、原子落盘、manifest、恢复、失败隔离 | 中断后续跑；已完成 chunk 不重算 |
| **V4 指数拟合 D**（3 周） | 选指数/拟合/报告 | 五指数、权重、池化、三情景、诊断 | 指数点位与逐券可追溯 |
| **V5 评论家/校准**（研究） | 迭代与鲁棒 | shadow/apply、合成目标、缓存/一致性、参数台账 | 同结论稳定率、采纳率 |

主路径 V0–V4 约 **15 周**；V5 研究线并行。

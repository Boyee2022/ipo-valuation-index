01

七步工作流

SEVEN STEPS
STEP 0
参数解析
四层阶梯取数，产物是解析台账 _parse_ledger，不是填满的模板
STEP 1
数据采集
抓取 ＞ 文档 ＞ 数据源 ＞ 检索；六路数据回填统一 JSON
STEP 2
画像评分
六模块画像 + 盈利质量评分卡（5 指标，基准 60 分）
STEP 3
产业链可比
图谱 + 三档可比 + 质量评分 + 环节中枢
STEP 4
引擎计算
多方法并行 + 四部分拆分；4b 统计校验，4c–4l 十个 opt-in 模块
STEP 5
情景博弈
五层机制叠加出 Bear/Base/Bull，再按 25/50/25 裁决
STEP 6
投行级报告
11 段、三口径并排、warnings 全列、八项机检

三条入口共用这条主链：一句话估值（自动解析并一次问清 ≤4 项）、 参数模板（填 input_template.json）、 增量重估（--compare 输出 diff 与收敛/发散）。 第四条「统计校验模式」不是入口，而是 A 级默认执行的横切层。

KEY DESIGN CHOICES

① 六阶段：阶段决定「用哪个工具」，而不是「重要几倍」

为什么弃用 k_lifecycle 乘数
旧乘数有三处硬伤：初创档舆情归一化后占 37.50%（是 DCF 的两倍）；成长档恒等 {1,1,1}，最需约束的档反而零调整；衰退与成熟的舆情占比只差 0.05pp。更根本的是语义错位——阶段问「用哪个工具」，乘数答「重要几倍」。 25 例仅改开关，Δ 落在 [−4.69%, +3.03%]；但 base 权重为 0 与 Layer 0 否决的路径不得被表复活， 统一记入 blocked_paths。

05

设计思想

FIVE PRINCIPLES
01 · 结构化先验优先于黑箱拟合

能用一张可读表表达的，就不写拟合或隐式系数：DAMODARAN_STAGE_WEIGHTS（六行三列）、 PLC6_SHAPE_PARAMS（n/CAP/形态）、TV_SHARE_GRADES（40/75/85）。 LLM 负责取数与叙事，不负责发明数值。

02 · 可审计证据链优先于结论

每个数字都能回答「从哪来」：可比七项判据 + 剔除理由枚举 + 状态机； growth_seq_detail[{t,g,src,clamped_by}] 逐年标来源； coefficient_detail 让权重可逐项复算。

03 · 边界护栏优先于「算得出来」

blocked_paths 防止被表复活；阶段间 n 与 CAP 违反直接抛错； 权益下限 max(0, net_cash) 守住股东有限责任；PEG 双道护栏； 终值占比 > 85% 禁出单点。宁可不出数，不出错数。

04 · 单一真源与版本化参数

常量集中在引擎顶部与 industry_params.json；报告层不自算、只渲染引擎输出。 参数库带版本（industry_params 1.0.1→1.0.3，calibration 有 default + case 覆盖），改表即改口径。

05 · 机器可检 + 诚实退化

170 个用例包含结构断言、反向断言、性质测试、AST 断言与逐字节零回归； 未选中的口径只输出 skipped + reason，不产数值——「算了但没用的数字，最终一定会被引用一次」。

07

局限与风险

LIMITS
  • 无真值。校验的是内部一致、可复算、可解释；没有一例用事后股价或发行定价做样本外检验，案例校验不等于回测。
  • 参数经验性强。六阶段权重、PoS 表、商誉折价档、情绪强度矩阵多为先验；形态差异对总估值上限约 2%，但 g₁/tg 选错会整体平移路径。
  • 样本覆盖窄。25 例落点 15/7/3/0/0/0，初创·年轻成长·衰退三档零实证——而这恰是 IPO 估值最需要的三档。
  • 复杂度高。引擎 5,681 行，十个 opt-in 模块彼此有仲裁规则；改一处要同时看常量、导入期断言、冒烟用例、报告披露。
  • LLM 报告层与引擎层的边界靠纪律。报告 11 段大量文案由引擎字段拼装，「渲染型自由文本未全量覆盖」同族缺陷已暴露 6 次。

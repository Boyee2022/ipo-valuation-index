# 大模型 IPO 智能估值（LLM IPO Valuation）v3.29.1

基于国金证券《基于大语言模型的上市公司智能估值模型构建》（李双宏、杨利国、王洪涛）的方法论：
**结构化财务指标与非结构化信息统一建模 → 类分析师逻辑分步骤推理 → 产业链挖掘 → 多方法并行估值
→ 增量维度修正（财报/舆情/商誉）→ 多情景博弈裁决 → 统计校验（MC/弹性/稳健性）→ 可解释可审计输出**。
方法论出处与文献映射详见 `methodology.md`；v2.0 案例校验见 `references/技能校验与完善报告.md`；v3.0/3.1/3.2 统计校验层依据见 `references/估值不确定性量化与校准报告.md`（两份报告为占位说明，缺失不影响执行，结论已沉淀于 methodology.md §5/§6）。

## 0. 使用方式（三条入口 + 统计校验模式）

### 入口 A：一句话估值（推荐，自动触发完整流程）
用户仅给一句话描述（如"某生物医药公司，近三年营收复合增长30%，净利润率20%，拟IPO，请估值"），
技能自动完成：解析参数 → 询问/补齐关键缺失参数（一次问清）→ 执行完整流程（含统计校验）→ 输出报告。

### 入口 B：参数模板估值
用户提供或确认 `assets/input_template.json` 中关键参数（行业、财务、质量明细、可比公司、募投、偏好、环节中枢），
技能据此执行完整流程。

### 入口 C：增量重估
对已有估值结果，用户提供新信息（新财报/新公告/行情变化），技能在保留原假设记录的基础上增量更新
（引擎 `--compare` 输出 diff：区间变化、假设变化、收敛/发散判定；对应论文"动态估值"主张）。

### 入口 D：统计校验模式（v3.0 新增，A 级默认执行；用户明确要求时强制）
当用户要求"对估值做蒙特卡洛/统计校验/置信区间/参数敏感性/稳健性检验/校准"时，技能自动进入本模式：
在引擎输出基础上调用 `scripts/stat_validation.py` 输出统计结论，并确保最终报告包含双口径估值区间。

## 1. 技能分级与横切维度

**技能分级**（决定执行强度与缺失处理）：
- **S（必须）**：每案必执行，有量化阈值与判断标准，缺失=报告不成立；
- **A（重要）**：默认执行，数据不可得时降置信度并显式标注，不阻断流程；
- **B（增强）**：数据可得时执行，缺失不影响主流程，报告标注"未校准"。

**横切维度（贯穿全部技能）**：
- X1 置信度管理：数据完整性×质量分×因子校准×统计区间宽度 → 综合置信度（高≥80 / 中60~80 / 低<60）；
- X2 审计留痕：假设溯源、参数版本、引擎与统计中间量可复算（固定 seed）；
- X3 幻觉防御：报告数字必须来自引擎/统计输出或文件原文，禁止 LLM 编造。

## 3. 完整工作流（7 步，每一步留痕）

```
Step 0 参数解析与确认 ── 一句话→结构化参数；四层阶梯取数（表述→采集→问询→默认）；一次问清（≤4项）；解析台账 + 置信度记录
Step 1 数据采集与统一建模 ── 财务/质量明细/非结构化/产业链/可比/规则 六路数据回填 input_template.json
Step 2 画像与质量评分 ── 六模块画像 + 盈利质量评分卡（S2.2）+ 财务异常识别（S2.3）
Step 3 产业链与可比分析 ── 产业链图谱 + 可比筛选 + 可比质量评分（S3.3）+ 环节中枢（S3.4）
Step 4 引擎计算 ── python scripts/valuation_engine.py（多方法 + 修正项分层 + 因子校准 + 确定性敏感性 + IPO约束）
Step 4b 统计校验 ── python scripts/stat_validation.py（蒙特卡洛 + 参数弹性 + 相关性 + 稳健性 + 修正区间）
Step 5 情景博弈与裁决 ── Bear/Base/Bull + 分歧项裁决 + 置信度合成（融合统计校验结论）
Step 6 输出估值报告 ── 双口径（情景区间 + MC 90%区间）/假设依据/统计校验/风险/溯源（assets/output_template.md）
```

### Step 0 参数解析与确认
- 用 LLM 将一句话/自由文本解析为 `assets/input_template.json` 字段，记录每字段**解析置信度**（高/中/低）。
- 必填参数（`required: true`）：行业类型、近三年营收或CAGR、净利润/净利率或亏损状态、拟上市板块。缺失时**一次问清**（≤4项）。
- 用户未指明板块时按营收规模推断：盈利+成长 → 科创板/创业板；未盈利+硬科技 → 科创板；传统行业 → 主板。

**取值四层阶梯**（v3.26.1，**不得跳层**）：任何字段按 `L1 表述 → L2 采集 → L3 问询 → L4 默认` 取数，台账标记 `stated/fetched/stated/default`。规则见 `assets/error_handling.md` §1.0。

| 层 | 何时用 | 关键约束 |
|---|---|---|
| L1 表述 | 一句话明确给出 | 分四类：硬数据可用｜比率可用但标「未勾稽」｜**模糊表述不得量化**（"毛利率较高"→必须去采集）｜前瞻表述落 `growth_forecast` 而非历史字段 |
| L2 采集 | 无表述 **且标的有公开披露** | 转 Step 1 四档优先级；**不得跳过本层直接落默认值** |
| L3 问询 | 无表述 **且标的无公开披露**（未上市/早期） | 并入「一次问清 ≤4 项」 |
| L4 默认 | L1–L3 均不可得，或用户说「你来定」 | 报告标「假设值 ⚠」+ 置信度下调 + 台账记 `default` |

**表述与数据的关系是三态，不是「谁优先」**（`error_handling.md` §1.2）：**一致**（偏离 ≤ 净利率 1pp / 增速 2pp / 金额 5%）→ 直接采用并**记录口径**（归母/扣非、合并/母公司）｜**矛盾** → 按营收/净利计算并披露差异，**派生比率不作裁决依据**（净利率是派生量、营收净利是原始量，口径不明的比率会整条传导进 NOPAT）｜**未表述** → 不落默认，转 L2。

**Step 0 的真正产物是解析台账，不是填满的模板**（`error_handling.md` §1.4）：输出 `_parse_ledger{entry, field_source(五类: stated/fetched/derived/default/assumed), field_confidence, asked, conflicts, defaults_applied}`。**约束**：`default` 与 `assumed` 不得计入「数据完整度」分子——否则填满模板即等于数据齐全，`factor=(0.7+0.3×完整性)×…` 退化为常数，X1 置信度管理失效；报告「数据完整度」须注明「其中 N 项为默认值」。

### Step 1 数据采集与统一建模
优先级：**①自动抓取（v3.12，最高档）**：`python scripts/fetch_data.py <code> --financials --consensus` 拉取公开披露财务
（归母净利档位 annual/quarterly/semiannual、经营现金流、FCFF、股本）与市场一致预期净利（EPS×股本），失败回退下一档；
②用户文档（招股书/审计报告，LLM 抽取）→ ③已连接数据源（westock-data / neodata）→ ④WebSearch（标注"公开检索未验证"）。
采集范围：**净利披露档**（net_profit_basis：年度归母净利/季度×4/半年×2/一致预期，公开披露与市场预期为最高优先级）；
**质量明细**（OCF/净利、应收/营收、存货/营收、毛利率3年趋势、非经常性损益占比、商誉比）；
**情绪明细**（板块热度、个股舆情、时间窗口默认30天）；**环节中枢**（产业链环节 PS/PE 中位基准）。
数据矛盾处理：**按 `error_handling.md` §1.2 的三态处理，不采用「优先用户文件」的二选一**——表述与结构化数据一致时采用并记口径、矛盾时按营收/净利计算并披露差异、未表述时转本步采集；矛盾点明确告知用户采用口径，不默默选择。
**默认开关写入（v3.16.1，流程层默认）**：建模完成后在 `preferences` 写入 `"lifecycle_mode": "auto"`——新案例据此按公开指标判别生命周期并驱动四形态增速（见 Step 4c Layer 1）。该默认只落在**输入文件**；引擎代码缺省仍为 `legacy`，未提供该键的旧输入保持逐位不变（零变化保证）。

**v3.26.0 增补**：新案例同时写入 `"lifecycle_classifier_mode": "v326"`，并**必须**提供 `financials.margin_history`（≥3 期）与 `financials.roic`——否则第二维失效、判别只能退到 `ambiguous_shrink`。若标的营收为负增长，**不要**图省事直接写 `meta.lifecycle_stage="decline"`：衰退期会附带 `n=5`／`tg≤0`／`zero_growth_or_nav` 一整套口径，对 ROIC 仍高于 WACC 的公司是方向性错误（格力误判代价约 −38%）。收缩应通过 `sub_stage=cyclical_shrink` + `growth_model` 的 `g₁`/`p` 表达（见 Step 4k/4l）。

### Step 2 画像与质量评分
- **六模块画像**（S2.1）：商业模式/行业定位/成长性/盈利质量/募投/风险；量化锚点：客户集中度（前五大>50% 提示）、研发费用率（>15% 高研发）、应收账款周转。
- **盈利质量评分卡**（S2.2，S级必做）：5 指标加权（OCF/净利 30%、毛利率趋势 20%、应收/营收 20%、商誉比 15%、非经常性损益 15%），基准 60 分，修正系数 = (score−60)/40×10%（±10% 内）。评分明细全部留痕。
- **财务异常识别**（S2.3，A级）：应收增速>营收增速、存货激增、毛利率与现金流背离 → 触发质量扣分与报告提示。

### Step 3 产业链与可比分析
- 产业链图谱（S3.1）+ 关键变量识别（用 WebSearch/图谱工具，无工具时 LLM 手工构建）。
- 可比筛选（S3.2）：同一环节→同模式→同规模；≥3 家，不足降级（`assets/ipo_rules_checklist.md` §4）。
  **筛选过程须留证据链（v3.20.0）**：长名单规模与分类基准、剔除台账（理由落枚举）、信息可得性截点、规模双口径、
  同一实体去重、会计准则、次新股——七项判据与状态机见 **Step 4g** 与 `ipo_rules_checklist.md` §4b。
  没有证据链的可比法结论，无法应对「发行 PE 高于可比中位数」的监管问询。
- **可比三档分类与优先级汇总（v3.13，S3.2.1）**：在 S3.2 筛选基础上，按四维匹配（同环节 segment / 同模式 mode / 同规模 scale / 同成长阶段 growth_stage）将可比公司自动分为 **最可比（4 维全中）/ 较可比（中 2–3 维）/ 一般可比（中 0–1 维）**。汇总采用**主档优先 + 逐级回退**：最可比样本数 ≥ `preferences.tier_min_samples`（缺省 2）时仅用最可比；不足则并入较可比，仍不足再并入一般可比。引擎输出 `comparable_tiers`（active / tiers 名单 / selected_tiers / tier_min_samples）与 `value_median_by_tier`（逐档倍数中位）。目标公司画像置于 `meta.target_profile`（四维）；可比公司可补 `segment/mode/scale/growth_stage`（与 target_profile 同名维度比对），或显式 `comparability`（most/fair/general）直接覆盖。**全部可选**：未提供 `target_profile` 或无可比含新字段时，整体归入最可比，汇总退化为旧 flat 均值（旧输入零变化）。
- **可比来源优先（v3.12，最高档）**：优先经公开研究报告/公开信息选取可比（comparables.source ∈ research_report/public_info/auto/user/none），研报与公开信息档为最高优先级；来源留痕（引擎 `comparable_sources` 块：档位计数 + 最低 priority）。
- **可比质量评分**（S3.3，A级）：同环节+20｜同模式+20｜同规模+20｜同成长阶段+20｜数据≤5交易日+20；**来源评分（v3.12 新增）：research_report +10｜public_info +5｜auto +3｜user 0｜none −10**；<60 分区间加宽 ±20%（none 占比 >50% 额外 +10%）。
- **环节估值中枢**（S3.4，B级）：填入 `segment_benchmark.median_ps/pe` 后引擎输出环节隐含估值，与可比法并列对比（偏差>30% 触发可比选择审查）。

### Step 4 引擎计算（点估计）
```bash
python scripts/valuation_engine.py <input.json> -o <output.json>
python scripts/valuation_engine.py <input.json> -o <out2.json> --compare <prev.json>   # 增量重估
# 可选情景覆盖：--scenarios '{"bull":{"growth_adj_pp":15,"multiple_factor":1.3}}'
```
引擎输出（全部可复算）：
1. **多方法与四部分拆分（v3.15.0，`preferences.four_part_mode` 缺省 true）**：估值结果按四部分独立加权合成——
   - ① **DCF 现金流贴现**（权重 `weights.dcf`，缺省 0.30；内在价值口径，不承受市场修正）；
   - ② **可比公司法**（权重 `weights.comparable`，缺省 0.50）：可比乘数合成值 `comp_v` × (1 + 盈利质量修正 + 商誉折价 + 因子校准) × (1 − 流动性折扣)。**注意（v3.16.2 口径澄清）**：`comp_v` 本身已含 `scenario.params.multiple_factor`（情景倍数 ×0.8/1.0/1.2，含 `sentiment_structure.impact_map.multiple_factor` 舆情假设层传导的倍数项）——故 ② **并非"零情绪"**：舆情的**假设层倍数传导**落 ②，**市场情绪标量**落 ③，两者分层不叠加（详见 §8.3 与"双重计数警戒"）；
   - ③ **市场舆情**（权重 `weights.sentiment`，缺省 0.20）：`comp_v × (1 + 情绪修正)`，**独立加权、不再并入可比法**；情绪修正 = clamp(板块热度 + 个股舆情 + 情景因子, ±10%)，**不含质量、不含流动性**（口径 B：与盈利质量彻底解耦）；
   - ④ **统计检验**：MC 的 P5–P95 分位区间（`stat_validation` 输出 `ci90`，本次口径不变）。
   - 合成式：`value = ②×w_comp + ③×w_sent + ①×w_dcf`；`four_part_mode=false` 逐位回退旧合成（情绪并入可比法），旧输入零变化。引擎输出 `synthesis.four_part` 分解块（①②③ 各值与权重 + ④区间引用）。
   - **PEG 护栏（v3.16.4，`preferences.peg_guard` 缺省 true）**：② 内的 PEG 子法对样本增速设门槛——`growth_pct < peg_min_growth_pct`（缺省 5%）的样本剔除。**近零正增速会使 `PE/增速` 虚高，单只此类可比即可污染中位数**：某案例六家可比仅 1 家为正增速（+1.3%）→ PEG 中位 14.86 → PEG 值被放大到市值的 12 倍；又因 `PEG值 = 利润 × PEG中位 × (g1×100)` 把增速重复计入，量级爆炸并主导 ② 合成。二道护栏：PEG 中位数 > `peg_max_ratio`（缺省 5.0）判定失真 → **PEG 整法弃用**（不做截断，避免注入错误数值），弃用原因进 `warnings`。剔除样本留痕 `peg.guard_excluded`，弃用留痕 `peg.dropped_by_guard`；全样本被剔除时挂无 `value` 的诊断块（不进 `synthesis.peg_value`）。置 `peg_guard=false` 逐位回退 v2.13.1 行为。
2. **增量维度修正（S4.2，论文三维度全量化）**：
   - 盈利质量修正（按 S2.2 评分卡）→ 仅作用于 **②可比法**；
   - 情绪修正：clamp(板块热度 + 个股舆情 + 情景因子, ±10%)，用户显式 `sentiment_adjustment_pct` 优先；**v3.15.0 已删除原"情绪×质量"交叉规则**（泡沫抑制/舆情错杀），确保 ③ 市场舆情不含任何质量信息 → 仅作用于 **③市场舆情**；
   - 商誉折价分级：商誉/净资产 <10%:0｜10~15%:−2%｜15~30%:−5%｜>30%:−8% → 仅作用于 **②可比法**；
   - 修正项归属：质量/商誉/因子 → ②；情绪 → ③；流动性折扣 → ②（③ 不折 liq）；
3. **因子校准层（S4.3）**：`ff_factor_adjust`（用户/LLM 基于多因子模型提供）与 `segment_benchmark` 环节中枢；两者均无时标注"未做因子校准"并降置信度一档；
4. **确定性敏感性（S4.4）**：增速×倍数矩阵（各轴 −20%~+20% 共 5 档）+ WACC 敏感性（−1%/0/+1% 三档），用于直观展示主变量方向；
5. **IPO 定价约束检查（S5.2）**：发行PE vs 可比中位偏离（>+30% 预警 / +10~30% 提示 / <-20% 提示）、募资匹配、募投增量、流动性折价、商誉风险；
6. **置信度合成（X1）**：factor=(0.7+0.3×完整性)×(0.6+0.4×质量/60)×因子校准系数 → 高/中/低。
7. **统计强化（v3.3，可选激活，缺省不改变 v3.2 输出）**：
   - `wacc_model`：CAPM 分解（rf/ERP/β/债务成本/资本结构/税率，β 去杠杆再杠杆），显式 wacc 优先模型作校验（偏差>1pp warning）；
   - `cashflow_statistics`：历史营收/FCF/OCF 序列统计特征（算术/几何均值、标准差、CV、OLS 趋势、R²）+ 增速假设校验（预测 vs 历史 CAGR 偏差>10pp warning）；
   - `growth_triangulation`：自身历史 CAGR + 可比增速中位 + 行业增速 三角校准营收/永续增长率（用户显式优先，未显式自动采用；`preferences.growth_weights` 可配权重）；
   - `comparable_metrics`：可比指标汇总表（PE/PS/EV-EBITDA/PB/净利率/ROE/EV-Sales/增速 的中位数/均值/样本数/CV）；
   - `industry_index`：行业指数隐含估值交叉验证（偏差>30% 提示；可比<3家降级基准；不并入综合权重）；
   - `sentiment_structure`：舆情事件/政策聚合 → impact_map（增速/净利率/WACC/倍数/终值增速的假设层调整，与市场口径 sentiment_adjust 分层）。
8. **DCF 参数强化与无可比替代（v3.4，可选激活，缺省不改变 v3.3 输出）**：

**兼容与迁移（v3.16.1 起；v3.16.2 补充仲裁规则）**：**引擎代码**开关缺省为 legacy/fixed/false → **未提供开关的旧输入输出逐位不变**（冒烟 T17/T69/T70–T79 覆盖）；**技能流程层**在生成新案例输入时默认写入 `lifecycle_mode="auto"`（Step 1），使新案例默认启用生命周期判别——**「新案例启用」与「历史输入不变」二者兼得**。历史案例如需复现旧口径，确保输入不含该键或显式写 `"legacy"`。**为何放在流程层而非改引擎缺省**：改引擎缺省会令全部历史输入数值改变（破坏零变化契约）；放在流程层则新案例生效、历史不受影响，且引擎保留逐位回退能力。

**三项仲裁规则（v3.16.2，消除同层机制互斥）**：
1. **权重施加顺序**：`Layer 0 判别门` 与 `B4 权重条件化` 同时开启时，**先 B4（normalize(base × k_lifecycle × k_admissible)）后 Layer 0 封顶**——`conditional` 档的 `dcf_weight_cap`（0.2/0.3）在 B4 之后施加，不再被 B4 重算覆盖；B4 的基准权重取**用户 `preferences.weights`**（非 DEFAULT 常量）。
2. **DCF 适用性判定优先级**：`layer0_check=true` 时以 **Layer 0 前提检验**为准（现金流可定义性优先于资产类型标签）；与 `asset_type` 适配器结论相反时留痕 warning。`layer0_check=false`（旧口径）时沿用 `asset_type` 适配器。

### Step 4d 全市场估值框架修订（v3.17.0；全部 opt-in，缺省逐位不变）

**背景**：路由表 `FRAMEWORK_ROUTES` 早已声明 `recommended_primary`，但该声明**只在报告层被渲染成文本**，引擎侧无计算分派分支；`dcf_weight_cap` 只能对 DCF 做减法，无机制做加法。**根因是候选方法集被写死为 `{dcf, comparable, sentiment}` 三路**。

| **P1 权重键集泛化** | `preferences.method_set_mode`（缺省 `"legacy"`；启用＝`"routed"`） | `resolve_method_set()` 按 `framework_check` 路由**动态构造候选方法集**，替代主方法可携带权重进入综合。系数口径 `w_i = A_i × R_i × D_i × k_lifecycle_i` 归一化：**A 适用性**（dcf 取 `dcf_weight_cap` 上限；替代方法按是否为 `recommended_primary` 取 1.0/0.5）｜**R 可靠度**＝`METHOD_MATURITY` × 数据完整度｜**D 独立度**（舆情与可比法共用 `comp_v` → 折减 0.7）｜`k_lifecycle` 沿用 B4 因子。cap=0 时从骨架**剔除 dcf 键** | `synthesis.four_part.method_set`（industry_class/candidates/resolved_weights） |

**RIM 参数口径**（`V0 = B0 + Σ RI_t/(1+Ke)^t + TV`）：
- `B0` = `rim.book_value_equity` ＞ `financials.net_assets` ＞ `net_assets_latest` ＞ `equity_book_value`；
- `ROE` = `rim.roe_steady` ＞ `financials.roe` ＞ `industry_params.金融.roe_steady`；
- `Ke` = `rim.cost_of_equity` ＞ `financials.ke` ＞ `industry_params.金融.ke` ＞ 有效 WACC ＞ 0.10 兜底；
- `ω`（持续因子，clamp [0.50, 0.95]）= `rim.persistence` ＞ 行业底座 ＞ 0.85；
- 每股 = 权益价值 / 股本（**单位口径：亿元 / 亿股 = 元/股**，与输入 `$note`「金额=亿元，股票=亿股」一致）。

**DDM 适用性护栏**（中证协口径：仅适用成熟期/分红稳定项目）——触发即写入 `applicability_warnings`：
1. `Ke ≤ g∞` → 直接返回 `value=None`（Gordon 不成立）；
2. 显式期股利增速 > 25% 或 < 0 → 告警「成长股不符合分红稳定前提」；
3. `Ke − g∞ < 2%` → 告警「分母过小，估值对参数极度敏感」；
4. 终值占比 > 85% → 告警「价值主要由永续假设承载，须做 g∞ 敏感性」。

**P1 系数分项（`coefficient_detail` 留痕）**：每方法输出 `base / A / R / D / k_lifecycle` 五项，供审计逐项复算；`METHOD_MATURITY` 基准：dcf 1.00｜rim 1.00｜ddm 0.95｜comparable 0.90｜sentiment 0.90｜nav 0.85｜sotp 0.80｜rnpv 0.60。

**零回归契约**：上表五项开关全部取缺省值时，输出与**显式关闭全部开关**逐位相同（`test_t99b_v317_zero_regression` 断言 byte-identical）；取代主方法（nav/rim/ddm/rnpv/sotp）仅在 `method_set_mode="routed"` 时才可能进入 `weights`。

**⚠ 已知未闭合项（v3.17.0 留痕）**：`rnpv` / `sotp` 已进入 **P1 候选集权重**（可携带权重参与综合），但 `0.6×rnpv 主线` 的 **rNPV 逐管线计算** 与 **SOTP 逐分部加总** 尚未实现——当前由 `comparable` 承担该部分权重。`nav`（净资产法）已有实现（`nav_valuation()`，此前以「不并入综合权重」身份空转，P1 后可由路由注入权重）。

### Step 4e 舆情强度驱动估值调整（v3.18.0；全部 opt-in，缺省逐位不变）

**背景**：v3.17.0 的 **P2 修正层**把舆情从「独立加权路径」降为「作用于可比法的乘性系数」，方向正确，但留下一个**结构性缺陷——双重截断冗余**：`sentiment_adjust()` 已把情绪值 clamp 到 **±10%**，`_sentiment_correction()` 又 clamp 到 **±band**（P4 分化后 mature 仅 5%）。两层截断叠加后，**内生信号强度 k_signal 的放大作用被完全吃掉**：

| 案例 | band | sentiment | k_signal | 未截断修正 | 实际（v3.17 口径） | 信号是否生效 |
|---|---|---|---|---|---|---|
| 成熟期企业 | 5% | +10% | 1.56（6 条高重要性一致） | 15.6% | **5.0%**（被 band 截回） | ❌ 放大被吞 |
| 成长型企业 | 10% | +8% | 1.38（4 事件+1 权威政策） | 11.0% | **10.0%**（被 band 截回） | ❌ 放大被吞 |

**v3.18.0 口径**：把「舆情方向」与「舆情强度」拆成两个**正交**因子，并解除 band 的硬天花板（口径 C）：

```
adj_sent = band × k_signal × sign(sent) × min(|sent| / 10%, 1.0)
adj_sent = clamp(adj_sent, ±band × SIGNAL_K_MAX)          # SIGNAL_K_MAX = 1.60
```

- `sign(sent)` —— 只承载**方向**（正/负），不再用 `sent` 的数值大小去乘；
- `k_signal` —— 承载**强度**（查矩阵，≥0），是唯一决定放大／缩小倍数的因子；
- `min(|sent|/10%, 1.0)` —— **信号成立度**归一化开关：`|sent| ≥ 10%` 即满权；`|sent| = 1%` 只给 1/10 的修正，**避免「无实质舆情却给满额修正」**；
- 上限放宽到 `band × 1.60` —— 承认强信号可有序突破基础带宽，同时保留硬上限防失控。

| 项 | 开关（缺省值） | 作用 | 输出块 / 键 |
|---|---|---|---|
| **① 方向／强度正交** | `preferences.sentiment_adjust_mode`（缺省 `"legacy"`；启用＝`"strength"`） | 由 `sent×k` 再截断改为 `band × k_signal × sign(sent) × min(|sent|/10%,1)`，消除双重截断 | `scenarios.{x}.sentiment_correction.signal.{direction,magnitude,adj_raw}` |
| **② 口径 C 解除天花板** | 随 ① 启用 | 上限 `band` → `band × SIGNAL_K_MAX`（1.60） | `signal.{ceiling, clamp_hit}` |
| **③ 强度矩阵表驱动** | 随 ① 启用 | `SIGNAL_STRENGTH_MATRIX` 查表替代 if/else 阶梯（详见下表） | `signal.{tier, base, consistency}` |
| **③a 权威出处加成** | `preferences.signal_authority_mode`（缺省 `"legacy"`；启用＝`"weighted"`） | policy 项 `authority=true` 时 ×1.15（新增，原实现仅高重要性 ×1.2） | `signal.authority` |

| **④ 去相关折让** | `preferences.sentiment_overlap_discount`（缺省 false） | 与 `impact_map.multiple_factor` **同源重叠**时对修正系数 ×0.70（沿用 B5 先例） | `signal.overlap_discount` |

**③ 信号强度矩阵 `SIGNAL_STRENGTH_MATRIX`**（量级 × 一致性 → 基础 k_signal）：

| 量级 \ 一致性 | consistent（方向一致） | conflict（正负共存） |
|---|---|---|
| **none**（n=0） | 0.50 | —（无信号不加成） |
| **few**（n=1–2） | 0.70 | 0.60 |
| **medium**（n=3–5） | 1.00 | 0.70 |
| **many**（n≥6） | 1.30 | 0.70 |

**强度加成链**（乘性叠加，最终 `min(k, SIGNAL_K_MAX=1.60)`）：

```
k = MATRIX[量级][一致性]
if 存在 importance=="high" 的事件:        k *= 1.20      # SIGNAL_HIGH_MULT
if authority=="weighted" 且 policy 有 authority:  k *= 1.15   # SIGNAL_AUTHORITY_MULT
if days_since_event > 30:                 k *= decay     # 线性或分段
k = clamp(k, 0, 1.60)
```

**企业类型带宽 × 强度上限对照表**（band 来自 P4，ceiling = band×1.60）：

| 企业类型 | band | 实际修正上限（ceiling） | 适用场景 |
|---|---|---|---|
| startup / growth_tech | ±15% | **±24.0%** | 早期科技、未盈利高成长 |
| growth | ±10% | **±16.0%** | 成长期 |
| cyclical | ±8% | **±12.8%** | 强周期（σ_ln>0.60 且有负增长） |
| mature / financial / decline | ±5% | **±8.0%** | 成熟期／金融／衰退期 |
| private | 0% | **0%** | 非上市股权（舆情不适用） |

**留痕结构**（`scenarios.{bear/base/bull}.sentiment_correction`）：
```
layer="correction"｜adjust_mode="legacy"|"strength"｜band_pct｜correction_pct｜impact_value
signal: { band, band_reason, k_signal, raw, magnitude, direction, adj_raw, ceiling,

```

**零回归契约**：四项开关全部取缺省值时，输出与**显式关闭全部 v3.18 开关**逐位相同；且与 **v3.17 全关**层叠后仍逐位等价（`test_t100i_v318_zero_regression` 双重断言）。守护＝**T100a–T100i 共 9 例**。

**⚠ 已知未闭合项（v3.18.0 留痕）**：④ 去相关折让目前仅按**固定 0.70** 折让，尚未按「事件类型 × `impact_map` 是否确实传导了 `multiple_factor`」做**条件化自适应折让**——当前实现仅在假设层（`sentiment_structure.enabled` 且 `impact_map` 非空）生效时折让，粒度较粗；后续可考虑按 `impact_target` 逐项判定重叠强度。

### Step 4f 路由主方法的引擎取值分支：rNPV / SOTP（v3.19.0；全部 opt-in，缺省逐位不变）

**背景（承接 v3.18.0 P6-A）**：P6-A 权重包络闸门只做了「**诚实退化**」——候选集中出现「有声明权重但无引擎取值分支」的方法时，把该权重归零并回流（消除静默少算）。但 rnpv/sotp 本身就是**空壳**：路由表 `ROUTE_METHOD_WEIGHTS` 为管线药企（`pipeline_pharma`）声明 `rnpv 0.60`、为控股平台（`holdco`）声明 `sotp 0.60`，引擎侧却无对应计算 → **声明即空转**。本版补齐两者的**引擎取值分支**，使「声明即计算」。

| 项 | B. rNPV 风险调整净现值 | C. SOTP 分部加总 |
|---|---|---|
| 适用路由 | `pipeline_pharma`（管线药企） | `holdco`（控股平台/多业务） |
| 开关 | `preferences.enable_rnpv`（缺省 false） | `preferences.enable_sotp`（缺省 false） |
| 输入块 | `input.rnpv{enabled, discount_rate?, margin?, pos_overrides?, pipelines[]}` | `input.sotp{enabled, net_debt?, associates_value?, holdco_discount?, segments[]}` |
| 核心公式 | `rNPV = Σ_t [ PoS × 风险调整现金流_t / (1+r)^t ]` | `EV = Σ(分部价值_i × 持股_i) + 联营 − 净债`；`股权 = EV × (1 − 控股折价)` |
| 方法成熟度 R | 0.60（最低——假设密集） | 0.80 |
| 输出结构 | `rnpv_valuation{value, per_share, pipelines_detail, pos_schedule, discount_rate, ...}` | `sotp_valuation{value, per_share, segments_detail, ev_sum, net_debt, holdco_discount, ...}` |

**B. rNPV 口径细节**：
- **阶段 → 上市成功率 PoS**（`RNPV_POS_TABLE`，业界区间中值，非精确统计）：preclinical 0.10／I 期 0.20／II 期 0.35／III 期 0.60／NDA 0.80／已上市 1.00；支持中文别名（一期/二期/三期/申报/已上市…）；可由 `rnpv.pos_overrides{"phase3": 0.9}` 逐管线覆盖。
- **概率加权方向**：仅对**上市后收益**乘 PoS；上市前研发成本（`rnd_annual`）按**确定性**计入（**成本不乘 PoS**）。这是保守且可审计的口径——若成本也乘 PoS，会人为抬高低成功率管线价值。
- **生命周期剖面**：上市后第 1–4 年线性爬坡至峰值 → 峰值维持 → 专利悬崖期（8 年）线性衰减 → 残值率 10%（`RNPV_RAMP_YEARS=4 / RNPV_TAIL_YEARS=8 / RNPV_TAIL_FLOOR=0.10`）。
- **折现率**：显式 `discount_rate` > 行业底座 `医药.rnpv_discount`（12%）> 缺省 12%。
- **留痕/守卫**：全部管线缺 `peak_sales`/`launch_year` 时返回 `value=None`（**不返回 0**，避免误读为「估值为零」），并给出逐管线 note。

**C. SOTP 口径细节**：
- **分部价值「输入 + 加总」模式**（`segment-value-in-and-sum`）：分部法价值由用户/外部按分部给（显式 `value`，或 `metric × multiple`），引擎只负责**加总桥**与**控股折价**，不在引擎内重跑各分部 DCF——保持**可审计**，与 NAV/成本法的「输入驱动」定位同族。
- **控股折价**：显式 `holdco_discount` > `auto_discount`（按有效分部数分档：1→0%／2→5%／3→10%／4→15%／5+→15%）> 缺省 0；硬上限 `SOTP_HOLDCO_DISCOUNT_MAX=0.40`。分部越多、异构度越高，折价越接近上沿。
- **守恒性**：单分部/无净债/无联营 → `value == Σ分部价值`（冒烟 T103 守护）。

**综合接入（关键修复）**：`scenario()` 综合式原只读 `comparable` / `dcf` 两键 → 本次扩展为**读取全部替代法取值**（`alternative_methods`），rnpv/sotp 按其（已由 `resolve_method_set()` 归一化的）权重**真正进入综合**。此前 rnpv/sotp 的权重是**静默蒸发**（权重写了、综合式不读 → 综合值被低估），比「空转」更严重；现已在 `scenarios.{x}.alternative_methods{rnpv/sotp: {value, weight, contribution}}` 逐位留痕。

**报告层**：`§7.1` 多方法表新增 rNPV/SOTP 行；`§6.3` 方法适用性表新增两行（定性模板 + 本案例适用性）；`§7.2` 综合推导新增 `＋ rNPV × w_rnpv` / `＋ SOTP × w_sotp` 行；`§7.3.2 rNPV 管线估值披露`（逐管线 PoS/峰值/上市/rNPV + 拆解）与 `§7.3.3 SOTP 分部加总披露`（分部表 + EV→股权加总桥）为**新增独立章节**；四行均在引擎未启用时**不渲染**（零回归）。

**⚠ 已知未闭合项（v3.19.0 留痕）**：
1. rNPV 的**专利悬崖剖面**为模板化近似（统一爬坡 4 年 / 衰减 8 年 / 残值 10%），未按瘤种/适应症差异化——后续可按 `pipelines[].profile` 覆写；
2. rNPV **未做管线间相关性折让**（同一平台的多条管线成功率往往相关，独立相乘会高估组合价值）；
3. SOTP 的**内部交易与共享成本**处理口径未统一（当前仅按持股比例加总，不消除分部间内部收入/费用）；
4. `pipeline_pharma` 路由的裸关键词 `"生物"` 会误命中「生物质能／生物农药」（见 v3.16.17 反向造词测试判据，叠加营收阈值后误路由 rNPV）——**残余风险未修**。

### Step 4g 可比公司筛选证据链（v3.20.0；全部 opt-in，缺省逐位不变）

**背景**：技能的 `comparables` 是外部输入（用户/研报），引擎此前只能「拿到什么就用什么」——既没有长名单，也没有剔除台账，更不校验可比数据是否越过了估值基准日。监管对「发行 PE 高于可比中位数」问询时（`ipo_rules_checklist.md` §2 第 1 条），第一个问题就是「你为什么只选这几家」，而技能答不出来。本步把筛选过程从外部黑箱变成**可审计的字段与判据**，口径对齐 CVA comps 技能第 2 步。

**技能边界（必须先讲清）**：技能不能自己去找可比公司。它能做的是 ① 要求输入附带筛选证据；② 在证据缺失时**降级而非阻断**；③ 把判据结果逐项留痕供报告引用。

| 期 | 判据 | 开关（缺省） | 作用 | 输出键（`peer_screening.stages.*`） |
|---|---|---|---|---|
| **一期 P0-1** 长名单/剔除台账 | `peer_screening.enabled`（false） | 校验五项：分类基准是否声明（否则长名单不可复现）｜长名单规模 ≥ 2× 最终样本（否则「筛选过粗」）｜有长名单必有剔除记录｜剔除理由落枚举 `REASON_TYPES`（自由文本不可统计）｜样本覆盖率 | `s1_long_list`（checks / coverage） |
| **一期 P0-4** 信息可得性截点 | `info_cutoff`（→ `meta.valuation_as_of`） | 财务期末晚于截点 = **用基准日后数据回填** → `violation`；滞后 > `max_lag_days`（270）→ `lagged` | `s1_cutoff` |
| **二期 P0-2** 规模双口径 5 倍 | `scale_multiple`（5.0） | 「标的收入 ÷ 长名单收入中位」与「标的市值 ÷ 长名单市值中位」**取偏离 1 更远者**为判定基数；>5× 或 <1/5× → **须先收窄到产品档次更接近的子组** | `s2_scale`（ratio / deviation / binding / exceed） |
| **三期 P0-3** 同一实体去重 | `accounting_gate` 同上启用 | `legal_entity_id`（回退 code 去交易所后缀）相同者**只计一次**；保留优先级 **A 股 > 市值更大 > 先出现**（估值环境一致优先，不因 H 股市值大而反选） | `s3_dedupe`（merged / kept_names） |
| **三期 P1-1** 会计准则闸 | `accounting_gate`（true） | `standard` 与 `meta.accounting_standard` 比对，跨准则标 `requires_reconciliation`（**标记不删除**——PS/PB 受影响较小，可按乘数用不同样本集） | `s3_accounting`（aligned / cross） |
| **四期 P1-4** 次新股剔除 | `seasoning_gate`（true）／`seasoning_months`（12） | 上市 <12 月 → 剔除（PE 含炒新溢价，IPO 定价陷阱）；12~24 月 → `watch`（保留但须做含/剔双口径） | `s4_seasoning`（excluded / watch） |
| **四期 P1-5** 指数锚降权 | `index_anchor_haircut`（true）／`index_fallback_level` | 级别 → 权重上限：`primary` 1.00｜`fallback_l1` 0.50｜`fallback_l2` 0.40｜**`fallback_l3` 0.30**（全样本口径，禁止与精选可比同级） | `s4_index_anchor`（weight_cap / basis） |

**状态机与降级契约**（`status` 与建议权重，替代「有/无」二态）：

| status | 触发条件 | `weight_keep` | `confidence_cap` |
|---|---|---:|---|
| `ok` | 有效样本 ≥ 5 且无致命问题 | 1.00 | — |
| `degraded` | 3 ≤ n < 5，或规模超 5×，或截点违规 | 0.50 | 0.75 |
| `weak` | n < 3 | 0.25 | 0.55 |
| `unavailable` | n = 0 | 0.00 | 0.40 |

**诊断模式 vs 执行模式（关键安全设计）**：

- **诊断模式（缺省，`enforce.filter_sample=false`）**：只产出 `status` / `problems` / `warnings` / 建议权重，**不改样本、不改任何数值**。守护 T109 断言「除新增块与 warnings 外全字段逐字节一致」。
- **执行模式（`enforce.filter_sample=true`）**：按 `eligible_names` 过滤 `self.comp` 后再进场景计算（会改变数值）。**过滤后为空必须阻止执行并保持原样本**——这是「原本能算、改完算不出来」的防线。
- **`enforce.weight_keep=true` 只产出建议值与 warning，引擎不自动改权重**：权重再分配属编排层职责，避免本模块静默改变数值。

**⚠ 已知边界（v3.20.0 留痕）**：
1. **长名单中位缺失时退化为最终样本中位作代理**（`basis="final_sample_proxy"`）——判定强度下降，报告须披露该口径，不得假装有长名单数据；
2. **`n_final` 与 `n_eligible` 是两个口径**：前者为去重后进入统计的样本，后者为进一步扣除次新/标记排除后的可用样本；
3. **次新判据对上市公司估值无意义**（它们本就有长期交易价格），该判据只在 IPO 定价场景发挥作用，故缺省开启但结论仅作披露；
4. 未解决：**可比公司「经营性」与「投资性」利润的拆分**（一家白电龙头含大量联营投资收益时 PE 失真）——须人工在 `incomparable` 字段说明。

### Step 4h 增速与永续增速参数（v3.21.0；全部 opt-in，缺省逐位不变）

**背景**：DCF 的估值结果对两个参数最敏感——显式期增速与永续增速。技能此前把它们处理成「一个默认值（6%）+ 一个 [0,10%] 区间校验 + 一个只算不判的 `tv_share` 字段」，而 CVA 把同样的事写成了四条不可绕过的断言。格力实测把抽象差距变成了数字：同一标的、同一套现金流，仅永续增速从 0% 取到 6%，权益就从 4,011 亿变到 13,689 亿（**3.4 倍**）。

**开关位置**：顶层 `dcf_growth` 块（不是 `preferences`——这是**建模口径**，须在报告关键假设章逐项溯源）。规则清单见 `ipo_rules_checklist.md` §4c。

| B3 | `lifecycle_mature_n_mode`（**table**，v3.27.0 前为 legacy_4） | `cva_7` 时成熟期显式期 4→7 年 | 终值占比结构性锁在 80%+，R6 门禁一开就永久告警（★v3.27.0：表值已改为 10/8/6/4，`cva_7` 退化为 opt-in） |
| B4 | `scenario_step_mode`（fixed） | `cva_sigma` 时步长 = clamp(近三年增速 σ, 2pp, 5pp)；历史 <3 期回退 fixed 并告警 | 固定 ±10pp 使 bear 首年增速**突破历史极值**（格力 −12.00% vs 最差 −9.89%） |
| B5 | `growth_terminal_mode`（asymptotic） | `forced` 时末端等差插值、末点 ≡ tg | 三个形态都是渐近线，永不到达 tg（tg=6% 时落差 −1.12pp），与「成熟期增速已稳定」矛盾 |

**⚠ 三个必须理解的设计取舍**：

1. **A7 的 g\* 是诊断工具，不是参数**。格力 g\* = −30.50%（显式期现值 988.49 + 净现金 788.48 已吃掉大半市值）——这说明**分歧不在永续假设**：tg 压到 0% 权益仍有 4,010 亿（市值 1.91 倍），压到 −2% 也还有 3,461 亿。此时任何 tg 调整都是无效动作，必须回头质疑现金流路径本身。报告 §7.3.4 会直接给出这个判读。
2. **B3 改的是可审计性，不是精度**。n=4→10 时权益只在 4,956.66 与 4,954.60 之间（差 0.04%），但终值占比从 80.5% 降到 58.3%——Gordon 终值锚定末期 FCFF，缩短显式期只是把同一批现金流挪进终值。所以 CVA 坚持 7 年的真实作用是**把价值来源压进 60–70% 的可审计区间**。★**v3.27.0 的反向修正**：既然 n 不改价值、只挪价值来源，就不该为了让成熟企业的占比落进区间而把它抬到 7 年（那会制造 growth 6 < mature 7 的倒挂）——现改为 10/8/6/4，成熟企业占比回到 70% 附近即为常态，**占比是诊断指标，不是要凑的目标**。
3. **B2 不代拟数值**。形态判定只输出 `history_case` + metrics + 处置规则；改数必须有业务驱动证据（订单/产能/政策）。引擎不承担「从历史形态反推未来路径」的职责——那是编造。

**报告披露**：开启任一开关后，§6.2 追加「终值占比档位／永续增速取值链／永续增速情景调整／历史增速形态」四行；§7.3.4 给出完整披露（守卫处置 + 取值链表 + 三情景 tg + 档位 + g\*）。

**⚠ 已知边界（v3.21.0 留痕）**：
1. **`gdp_cap` 4.5% 是全国口径**，未按行业分化——公用事业/消费的合理长期增速低于此，极端档告警可能偏松；
2. **B4 的 σ 只取近三年**，样本短（3 期）时 σ 估计不稳，故 clamp 到 [2,5]pp 兜底；
3. **A3 `chain` 模式依赖 `industry_params.json`**，本轮补了「家用电器」类目（原白电回落「消费」类，`g_lt` 3%／`pe_med` 22× 与白电实际不符）；未覆盖行业仍回落 `default`；
4. **B5 `forced` 只强制末点**，中间路径形态仍由生命周期决定——CVA 的等差式对平坦路径适用，对 S 曲线会抹掉增速信息，故不做唯一形态。

### Step 4i 估值缺陷修复六项（v3.22.0；全部 opt-in，缺省逐位不变）

**背景**：对 v3.21.0 做审计时发现六类缺陷，共同特征是「**让估值系统性偏离，且不报错**」——错在数上、不在接口上。这类缺陷不会让流程失败，只会让报告看起来专业而数字偏掉，因此必须用建模口径块显式承载。

**开关位置**：顶层 `dcf_cost` 块（6 项）+ `dcf_growth.require_explicit_wacc_with_cva_tg`（1 项）。全部取缺省时输出与 v3.21.0 逐位一致。

| # | 缺陷 | 开关（缺省） | 根因与后果 | 启用后行为 |
|---|---|---|---|---|
| ① | WACC 缺省硬编码 11% | `dcf_cost.wacc_default_mode`（`legacy_11pct`） | `DEFAULT_WACC=0.11` 是 rf 1.9% 时代的旧值。不填 WACC 时 DCF 被系统性低估三成以上；填了又没人核口径 | `capm_auto`：按 `rf + β×ERP + 债务成本` 动态构造，挂 `wacc_default` 块（rf/erp/β_L/WACC/delta_pp） |
| ①b | ERP 口径混乱 | `dcf_cost.erp_default_mode`（`auto`） | 缺省 5.5%（Damodaran）与 CVA 隐含 ERP 8.04% 是两套口径，混用则 WACC 差 2.5pp×β | `auto`＝capm_auto 时取 **CVA 8.04%**、否则 5.5%；`erp_source` 逐档标注 |
| ② | p0 声明但不执行 | `dcf_cost.cashflow_fallback_mode`（`silent`） | `cashflow_model=p0_value_driver` 缺 ebit/roic 时静默回退比率法。用户以为用了守恒律口径（`g=ROIC×RR`），实际跑无再投资约束的比率法 | 恒留痕 `cashflow_model_fallback`（缺失项 + 降级去向）；`error` 模式再降置信度封顶「中」 |
| ③ | 可比法静默归零 | `dcf_cost.method_drop_mode`（`zero_silent`） | `comp_v = ... or 0.0`：可比法不可用时取 0、权重仍占 50%，综合值只剩 DCF 的 30%，**不报错** | `renormalize`：剔除可比法（及共用 `comp_v` 的舆情路径）并按剩余权重再归一，挂 `method_drop` 块，`comparable_raw` 输出 `null` 而非 0 |
| ④ | 重资产口径失配 | `dcf_cost.fcff_suggest`（false） | 资本开支/营收 >8% 仍走比率法（漏扣 capex），FCFF 系统性偏高；引擎知道 capex 强度却不提示 | 主动告警并给出 `fcff_suggestion`（capex 强度 / 阈值 / 是否已具备 ebit / 建议动作） |
| ⑤ | tg 与 WACC 不联动 | `dcf_growth.require_explicit_wacc_with_cva_tg`（false） | 只把 tg 从 6% 改 2%、WACC 仍 11% 时，终值倍数 `(1+g)/(WACC−g)` 由 **21.20×→11.33×（−46.6%）**，用户以为只动了永续假设 | 可复算告警（同时给出两档倍数与降幅），提示补显式 `wacc` 或开 `capm_auto` |
| ⑥ | 极端终值仍出单点 | `dcf_cost.point_estimate_guard`（false） | A6 对 >85% 只封顶置信度「中」，中枢照出，读者照样采信那个数（CVA comps 是 `point_estimate=null`） | `synthesis.point_estimate=null` + `point_estimate_suppressed`（档位/理由/处置路径）；**区间与 MC 90% 仍有效** |

**三个必须理解的口径点**：

1. **`capm_auto` 的语义是「无显式 WACC 时的动态替代」，不是覆盖用户值**。`financials.wacc` 显式给出时仍优先，CAPM 只作偏差校验（>1pp 告警）——这与 v2.5.0「用户显式 > 公开参考」的既有原则一致。
2. **ERP 是这六项里对中枢影响最大的一项，且量级远超其余五项之和**。格力实测：ERP 8.04%→5.5% 使每股 65.29→89.38（+36.7%）；而六项中另外五项对格美两家**全部未触发**（有可比、capex 轻、终值占比 63%、非 p0）。这说明 ①–⑥ 中的 ②③④⑥ 是**防错**、①①b⑤ 才**改中枢**。
3. **报表级 FCFF 与「净利×比率」在 capex 正确时等价**。格力 capex 按 CVA 的 FCFF 反解（125.31 亿）后，`fcff_mode` 给 66.29 元 vs 比率法 65.29 元（差 1.5%）；美的 108.85 vs 111.95（差 −2.8%）。**口径分歧全部来自 capex 数据，不来自方法**——这也是 ④ 的价值：把「数据错」和「方法错」分开。

**报告披露**：开启任一项后，§6.2 追加「WACC 取值来源／ERP 口径」两行；`wacc_default`、`cashflow_model_fallback`、`fcff_suggestion`、`method_drop`、`point_estimate_suppressed` 各自在触发时挂出并被报告引用。

**⚠ 已知边界（v3.22.0 留痕）**：
1. **`capm_auto` 的 β 在无 `wacc_params` 时只能靠 `industry_beta` 参考表兜底**（default 1.00），对 β 显著偏离 1 的行业会引入误差——正解是补 `unlevered_beta` 或用 `beta_estimator.py` 公开回归；
2. **④ 的 8% 阈值只能拦「capex 偏高」，拦不住「capex 异常偏低」**：格力 capex 曾误填 7.30 亿（应 125.31 亿），强度仅 0.45%，低于阈值故不告警，但开 `fcff_mode` 会高估 46.6%。**该场景须靠输入校验（`capex` 与 D&A 的量级关系）而非本开关**；
3. **CVA 的 8.04% ERP 是「隐含 ERP」，配的是修正 CAPM + 规模溢价**；本技能只移植 ERP、未移植规模溢价表，对小市值 IPO 标的仍偏松（后续可补十分位表）；
4. **`renormalize` 只处理「可比法整体不可用」，不处理「可比法可用但样本过少」**——后者由 `peer_screening` 的 `weight_keep` 表达，两者尚未打通（`enforce.weight_keep` 仍只产建议值）。

### Step 4j 单输出多候选：未选中的口径不产数值（v3.24.0；`fcf_ratio_lazy` 缺省 false → 逐位不变）

**背景**：`run()` 原**无条件**调用 `fcf_ratio_analysis()`。当 FCFF 口径已由更高优先级路径确定时，该比率没有任何消费方，却照样完整算一遍并挂进输出。格力 R3（`fcf_basis=statement_drivers`，即三表联立）实测：比率真值 **1.541** 被 `min(1.5, …)` **静默截断**成 **1.50**，既非真值、也非被采用的口径，却写进报告并被误归因为「P0 披露档」。

**铁律**：

> 所有**互斥候选**中，只有被选中的那支计算数值；未选中的支只允许输出「未采用 + 原因」，**不允许输出数值**。
> 理由：**任何「算了但没用」的数字，最终一定会被引用一次。**

**FCFF 口径的四级优先级**（`valuation_engine.py` `dcf_valuation()`，自上而下回落）：

| 级 | 触发条件 | `fcf_basis` | 形态 | 是否需比率法 |
|---|---|---|---|---|
| ① | 顶层 `dcf_drivers` 齐备 | `statement_drivers` | 收入→EBIT→NOPAT→+D&A−Capex−ΔWC **逐年**（三表联立） | ❌ 不需要 |
| ② | `financials.fcff_mode=true` + ebit/capex | `fcff` / `fcff_by_year` | 报表基期单点外推 | ❌ 不需要 |
| ③ | `cashflow_model=p0_value_driver` + ebit + roic | `value_driver_p0` | `NOPAT×(1−g/ROIC)`，含再投资约束 | ❌ 不需要 |
| ④ | 以上全缺 | `net_profit_ratio` | 净利 × FCF/净利（三层校准） | ✅ **主口径** |

| 项 | 开关（缺省） | 作用 | 输出键 |
|---|---|---|---|
| **F1 惰性求值** | `dcf_cost.fcf_ratio_lazy`（false） | 报表族命中时**不计算**比率法，输出 skipped 声明 | `fcf_ratio.{skipped, switched_to, reason}`；`assumptions_summary.dcf.fcf_ratio=null` + `fcf_source="未计算：FCFF 口径=…"` |
| **F1 诊断索取** | `preferences.diagnostics_fcf_ratio`（false） | 强制求值供**阶梯对照**（R2 vs R3 差多少），标 `role="diagnostic_only"` | `fcf_ratio.role`、`comparable_set_usage.fcf_ratio_source`（尾注「仅诊断对照，未进入估值」） |
| **F2 clamp 留痕** | 随 F1 所属路径，恒生效 | 比率越界不再静默截断 | `fcf_ratio.{clamped_from, clamp_bound}` + warning |
| **F3 OCF 质量触发** | `dcf_cost.fcff_suggest`（false） | 第二个「比率法失真」触发面（原只看 capex 强度） | `fcff_suggestion.trigger ∈ {capex_intensity, ocf_quality}` |

**三个必须理解的口径点**：

1. **惰性 ≠ 不准确**。惰性只改「算不算」，不改「算出来是多少」。④ 档原先在 `_fcf_ratio` 为 None 时退回裸 `ocf_to_net_profit`，使**三层校准在最需要它的档位静默降级**；改为按需求值后，④ 档一定拿到三层校准值（守护 T141 断言 lazy 与 legacy 的 `used` 与权益逐位相同）。
2. **`skipped` 是「未计算」，不是「缺失」**。字段永远存在并给出 `switched_to` 与 `reason`，否则读者无法区分「比率法不适用」与「引擎忘了算」。报告层据此渲染「未计算：FCFF 口径=statement_drivers（比率法未被采用）」，而不是打出一个暗示主口径用了比率法的假数。
3. **`fcff_suggest` 的两面触发不可互相替代**。格力 capex/营收仅 **1.01%**（远低于 8% 阈值 → 原雷达**完全沉默**），但其 OCF/净利 **1.60** 含并表财务公司的「吸收存款」，比率法同样失真（实测与报表级差 **−30.55%**）。「重资产高 capex」与「轻资产但 OCF 污染」是两个独立盲区。

**零回归契约**：`fcf_ratio_lazy=false`（缺省）时输出与 v2.21.1 **逐位相同**——比率块不得新增 `skipped`/`role`/`switched_to` 键（T143 双重断言：缺省 vs 显式写 false 逐位等价；且 `enabled=false` 时仍沿用「块不挂出」旧契约）。守护＝**T140–T145 共 6 例**。

**⚠ 已知边界（v3.24.0 留痕）**：
1. `preferences.diagnostics_fcf_ratio` 的对照值仍受 1.5 上界约束（现在会同时给 `clamped_from`，可看出真值）；
2. `fcff_suggest` 的 `ocf_quality` 判据只认 `financials.ocf_to_net_profit` 一个标量，**不解析现金流量表附注**——若输入未给该字段则不判（宁可漏报，不猜数）；
3. 惰性模式**不适配**「同一进程内多标的串行估值」的缓存复用场景：`_fcfr_done` 是实例级状态，跨 Engine 实例不复用。

### Step 4k 增速路径与永续增速建模（v3.25.0；两个新块缺省不激活 → 逐位不变）

**根因（两层）**：

1. **逐年增速没有模型，只有平移**：原 `build_growth_schedule()` 的五种形态（`exp` / `mean_revert` / `s_curve` / `decline` / `linear`）中，`rho=0.30` / `half_life=3` / `lam=0.30` **全部无出处**；且指数形态的渐近线**数学上永不到达 tg**（tg=6% 时末段仍差 −1.12pp），只能靠 `growth_terminal_mode="forced"` 在末端硬覆盖——即「模型给出的是近似值，再用规则把它改成正确值」。
2. **永续增速只有链式回落，没有交叉验证**：`resolve_terminal_growth()` 是「用户显式 > 行业 g_lt > 通胀锚」的**逐级回落**，取值完全取决于**哪一级先命中**。行业参数一命中，SGR 与市场隐含 g* 就被整段弃置——**用单一口径冒充交叉验证**。

**A 逐年增速：状态空间分解（`financials.growth_model`）**

```
g_t  = μ_t + u_t                              增长率 = 趋势 + 冲击
μ_t  = tg + (μ₀ − tg)·(κ^(t−1) − κ^(n−1)) / (1 − κ^(n−1))     趋势层（归一化指数）
u_t  = (g₁ − μ₀)·(1 − (t−1)/(n−1))^p                           冲击层（幂次）
```

三层闭合由**构造**保证，不靠外部覆盖：`t=1 → u=0, μ=μ₀ ⇒ g₁ = g₁`（首年精确通过、不打折）；`t=n → u=0, μ=tg ⇒ g_n = tg`（末端精确闭合）。

| 参数 | 语义 | 缺省 | 标定依据 |
|---|---|---|---|
| `p` | 冲击形态 | 1.5 | 周期性冲击（国补退坡/去库存）1.0 ／ 混合 1.5 ／ 结构性（份额流失）2.0 |
| `kappa` 或 `cap_life_years` | 趋势退化率 | κ=0.90（CAP=10 年） | `κ = 1 − 1/CAP`；CAP 中位 10–15 年（Rappaport 1986 / Mauboussin 1997） |
| `mu0` | 中期锚 | `= tg` | `mu0_mode`：`tg_default` ／ `industry_g_lt` ／ `industry_share`（行业 g_lt × 份额漂移）／ `median_anchor`（历史中位） |
| `g1` | 首年增速 | 自动分级 L1–L7 | `explicit` ＞ `user_path`（用户路径首年，**不冒充实测**）＞ `shape_rule` ＞ `fallback`（**必须标注非实测**） |

**双约束**：① 上限 `min(GDP 4.5%, SGR=ROIC×(1−派息率))`、下限 `floor`（缺省 −30%），逐行留痕 `clamped_by`；② **约束⑤**：`|μ₀ − g₁| > 5pp` 时 `μ₀` 退化为 `g₁`——防「趋势线往 tg 退、冲击线往 μ₀ 收」两方向打架产生的 **V 型非单调路径**。该退化**只对真锚生效**；`μ₀` 缺省取 `tg` 时它只是「没有中期判断」的占位，若也触发，等于把趋势层从「向 tg 收敛」改成「等于 g₁」，反把趋势层抹掉（格力 `|2%−(−7.6%)|=9.6pp` 即误触发情形）。

**接管语义（关键）**：`enabled=true` 只是「装好武器」，`override_manual=true` 才是「开火」。缺省尊重用户显式路径（L1 输入），只在该路径缺失时生效；接管时不覆盖首年（用户给的首年仍精确通过），只接管第 2 年起。

**B 永续增速：三锚取中位 + 双上限（`financials.terminal_growth_model`）**

| 锚 | 含义 | 缺席/剔除条件 |
|---|---|---|
| `industry_g_lt` | 行业长期增速（结构锚） | 行业参数未命中 |
| `implied_market` | 由市值反解的隐含 g*（定价锚） | **解 ≤ 0 时剔除**（残值非正说明市场隐含收缩，不能参与中位） |
| `sgr` | `ROIC×(1−派息率)`（结构硬约束） | 缺 `financials.roic`；**不猜分红率**（缺则取 0 使 SGR=ROIC 上界最宽并留痕） |

合成：`median(可用锚)`（可切 `combine="mean"`）→ `clamp(·, floor, min(gdp_cap 4.5%, WACC − spread_min 3pp))`。

**取消 6% / 2% 双轨缺省**：6% 与同文件 `TERMINAL_GROWTH_PUBLIC["gdp_cap"]=4.5%` **自相矛盾**（缺省值突破自己设定的 GDP 上限），且 `(1+g)/(WACC−g)` 在 8.14%+6% 时 spread 仅 2.14pp，属脆性区（±50bp 参数误差即可动估值 20% 以上）——退役为 `legacy_assumption` 只读基线。2% 的实质是「通胀 2% + 实际增长 0」，该留在**通胀锚/硬下限**位置，不该兼任缺省值（每 1pp ≈ ±11% 权益）。`min(通胀, GDP)` 双上限不可取：`min(2%,4.5%)=2%` 退化为单点，参数变常数、护城河无法定价。

**输出键**：`scenarios.{bear,base,bull}.dcf.growth_model{model,p,kappa,cap_life_years,g1,g1_source,mu0,mu0_source,mu0_degraded,mu0_clamped_by,u1_pp,bounds,closure,shock_flag}`、`dcf.growth_seq_detail[{t,g,src,clamped_by}]`、`assumptions_summary.dcf.tg_anchors_v2{anchors,skipped_anchors,raw,value,caps,capped_by,spread}`。报告层新增 **§7.3.5 增速路径披露**（逐年 g/μ/u/来源）与 §7.3.4 ⑥ **三锚交叉披露**。

**零回归契约**：两个块缺省（或显式 `enabled=false`）时，`scenarios` 与 `assumptions_summary` **逐位相同**（T150 双重断言）。守护＝**T146–T150 共 5 例**。

**⚠ 已知边界（v3.25.0 留痕）**：
1. `μ₀` 是路径唯一的自由判断，且**方向反直觉**——调高 `μ₀` 会使 `u₁` 更负（冲击更深），权益不一定上升（美的 `μ₀` 2%→4.88% 时权益从 −4.78% 变 −5.95%），报告不得按「锚越高越乐观」解读；
2. 缺份额漂移数据时 `μ₀` 取不到非 `tg` 值，趋势层退化为常数，路径实际只由 `p` 一个参数决定——这是**自然退化**，不是缺陷，但须在报告说明；
3. 分类器不会退役：`classify_lifecycle()` 的 5 个下游仅 1 个（原 `build_growth_schedule` 的形态/n/terminal）被替换，`k_lifecycle`／舆情强度／路径权重／报告披露仍在用；但新模型下**分类错误的误差从「有界」变「无界」**（形态选错只是曲线形状错，`g₁`/`tg` 选错会整体平移路径）；
4. `p` 是**深度负增长标的的专属敏感参数**：`p` 从 1.0→2.0，美的权益极差 **0.45pp**、格力 **6.94pp**（`p` 决定负增长区停留年数）；
5. 现有判别 `cagr_3y<0 → decline` 会把格力误判为衰退（营收 CAGR −3.4%，但净利率 12.28%→17.02%），须补第二维拆 `cyclical_shrink` / `structural_decline`——**本轮未做**。

### Step 4l 生命周期判别：营收负号不等于衰退（v3.26.0；`lifecycle_classifier_mode` 缺省 legacy → 逐位不变）

**两个硬伤**：

1. **`financials.cagr_3y` 从不自动计算**——全脚本 3 处引用全部是读取，没有一处从 `revenue_by_year` 推出来。输入不给该字段时 `classify_lifecycle()` 的 `cagr is None` 一路落到最后的 `else`，判成 **growth（conf 0.55）**。格力 R3 输入正是如此，只是被 `meta.lifecycle_stage="mature"` 显式覆盖才没暴露。
2. **`cagr_3y < 0 → decline` 是一维剪影**。它把三种处境压成同一个负号：

| 处境 | 营收 | 净利率 | ROIC−WACC | 该用什么 |
|---|---|---|---|---|
| 周期性退坡（国补退坡） | ↓ | ↑ | **>0** | 成熟期 + 收缩标记，`p=1.5` |
| 结构性衰退（需求消失） | ↓ | ↓ | **<0** | 衰退期（`decline` 配置） |
| 主动砍低毛利（组合优化） | ↓ | ↑ | >0 | 成熟期 + 收缩标记，`p=1.0` |

用同一个 `decline` 配置对待三者，会把 **ROIC 仍高于 WACC、还在创造超额回报**的公司当清算标的。`LIFECYCLE_DEFAULTS["decline"]` 的破坏力：`n=5`、`tg` 压至 ≤0、`terminal=zero_growth_or_nav`、`rr_mode=shrink`。引擎实测：格力误判 decline 后 DCF 从 91.35 → **70.47 元（−22.9%）**（美的同样误判 105.84 → 83.15，−21.4%）。若按纯零增长锚算约 56.9 元/股（NOPAT 250.8 亿 / WACC 7.87%），那是理论下限——引擎仍保留显式期的正增长，只是把终值增速压到 0。

**v326 口径判据（第二维）**

| 维度 | 指标 | 阈值 |
|---|---|---|
| A 规模 | `cagr_3y`（缺输入时由 `revenue_by_year` 反算 3 年 CAGR，需 ≥4 期） | 符号 + `|CAGR|<5%` 低个位数门槛 |
| B 盈利质量 | `margin_history` 首末差 | ±1pp 噪声带（该字段原只被情景步长消费，判别层完全没用） |
| C 资本回报 | `roic − wacc` | 以 0 为界，不设人为阈值 |

判定顺序：`净利率↑ 且 ROIC>WACC → cyclical_shrink` ｜ `净利率↓ 且 ROIC<WACC → structural_decline`（唯一进 `decline` 的组合） ｜ `净利率↓ 但 ROIC>WACC → ambiguous_shrink`（量价背离，交 LLM 判成因） ｜ `|CAGR|<5% 且 ROIC>WACC → mild_shrink` ｜ 其余 `ambiguous_shrink`。

**不新增顶层阶段**，只给 `mature` 加子标记 `sub_stage`：`cyclical_shrink` / `structural_decline` / `mild_shrink` / `ambiguous_shrink`。理由：收缩这件事 `growth_model` 用 `g₁` + `p` 已经表达清楚，不必动终值口径。

**显式阶段不夺权，但冲突必须告警**：用户给的 `meta.lifecycle_stage` 优先执行；若显式判衰退而客观指向周期性收缩（或反之），输出 `objective_conflict_with_explicit` + warning，并在报告 §6.2 标 ⚠。

**输出键**：`lifecycle.{classifier_mode, sub_stage, sub_stage_label, reason, objective_conflict_with_explicit}`、`lifecycle.evidence.{cagr_source, dim2{margin_delta_pp, roic_wacc_spread_pp, thresholds}}`。报告 §6.2 渲染「成熟期·周期性收缩」+ 判定依据。

**同时修复（与判别相邻的一个真 bug）**：衰退期 `tg` 上限 `if stage == "decline": tg = min(tg, tg_floor)` 原写在 lifecycle elif 分支内，`growth_model` 接管时整条被绕过——判了 decline 却仍按正 tg 算终值。修复要点是**位置**：必须在**选路之前**、且必须在 `growth_model_schedule(tg)` **求值之前**（否则路径末端按旧 tg 收敛，产出「terminal_growth=0 而路径末年=2%」的断裂）。

**零回归契约**：`lifecycle_classifier_mode` 缺省即 legacy——只读输入 `cagr_3y`、不产 `sub_stage`、note 文本逐字保持 v3.25.0 口径。守护＝**T151–T154 共 4 例**。

**⚠ 已知边界（v3.26.0 留痕）**：
1. `margin_history` 少于 3 期或 `roic`/`wacc` 缺失时第二维失效，只能退到 `ambiguous_shrink` ——**宁可说"待定"，不猜**；
2. legacy 路径（`build_growth_schedule` 的 asymptotic 形态）末端仍不精确到 tg，与 `terminal_growth` 存在断点；该问题由 v3.25.0 `growth_model` 从构造上解决，但两套路径并存期间断点仍在；
3. 第二维只判「是否衰退」，判不出「为什么收缩」——`p` 仍须 LLM 按成因定（周期 1.5 / 份额流失 2.0 / 主动砍业务 1.0）。

### Step 4b 统计校验（S4.5，A 级默认执行）
对引擎结果中的**主观参数**做系统性统计检验，输出统计置信区间与参数影响度：
```bash
python scripts/stat_validation.py <input.json> <engine_output.json> -o <stat.json>
                 [--case <case_id>] [--n 3000] [--seed 42]   # case 可选：覆盖案例级校准（如 cxmt/deepseek）
```
统计校验输出（全部可复现，固定 seed）：
1. **蒙特卡洛模拟**（默认 3000 次）：按 `assets/calibration_params.json` 先验分布对 WACC/净利率/终值增速/营收增速/可比倍数/情绪/质量明细联合抽样 → 估值分布 → **P5-P95 的 90% 预测区间**、中位数、直方图数据；
2. **参数弹性（OLS）**：每个参数单独 ±1σ 点扰动 → 估值变化% → 影响度排序（识别估值的主导主观变量）；
3. **相关性**：MC 样本中 参数扰动值 vs 估值 的 **Spearman 秩相关**；
4. **稳健性检验**：3 种方法权重方案（可比主导/DCF 主导）+ 可比极端样本剔除 → 中枢变化%；
5. **修正估值区间**：原始情景区间 ∩ MC 90% 区间 + 稳健中枢（MC 中位数与原始中枢均值）。

**分工边界（避免与确定性敏感性混淆）**：
- S4.4 确定性敏感性 = 单变量两档点扰动（增速×倍数矩阵、WACC±1%），用于直观展示主变量方向，引擎内置；
- Step 4b 统计校验 = 全参数联合分布抽样（连续分布+置信区间+弹性+相关性+稳健性），用于量化主观判断的整体不确定性带宽，stat_validation.py 输出；
- Step 5 情景博弈 = 三档离散情景（Bear/Base/Bull 点估计），用于裁决综合中枢；
- 三者互补：报告以 Step 5 中枢 + Step 4b 统计区间为双口径，S4.4 矩阵作为过程展示。

**统计校验结果解读规则（v3.0 实证校准；v3.2 新增字段）**：
- 读取 `monte_carlo.success_rate`（样本成功率）与顶层 `validation_passed`：成功率 <95% → 报告顶部强制标注"统计校验未通过（样本失败率 {x}%）"并列出失败原因；
- MC 中位数偏离点估计 <±15% → 点估计稳健，维持原中枢；
- MC 90% 区间宽于情景区间 >±20% → 置信度表述降一档，以统计区间为主口径；
- 弹性排序揭示主导主观变量（如未上市 AI 公司倍数弹性 +40% 主导、周期股增速/倍数双驱动）→ 报告中重点披露该变量的数据质量与假设依据；弹性已输出双向（`delta_pct_1sigma` / `delta_pct_minus_1sigma`）与方向校验（`direction_flag`，异常时检查 clamp 是否作用于乘子；顶层 `elasticity_issues` 聚合全部异常，非空时报告须披露并复核扰动逻辑）；
- 修正区间 = 原始情景区间 ∩ MC 90% 区间（统计带宽外极端情景自动淘汰）。

### Step 5 情景博弈与裁决
- Bear/Base/Bull 参数默认：增速 ±10pp、净利率 ∓3pp、倍数 ×0.8/1.0/1.2、WACC ∓1pp；可 `--scenarios` 覆盖。
- 裁决权重默认 25/50/25（可配置；v2.1 起自动归一化，和≠1 时引擎 warning）；分歧最大的假设（通常为增速或退出倍数）输出差异说明。

**⚠ 悲观/中性/乐观不是单一开关，而是五层机制叠加（定位与优先级）**：
1. **L1 离散三情景默认**（主）：`valuation_engine.py` `SCENARIO_DEFAULTS`（bear/base/bull 各 5 参数）→ 在 `scenario()` 内施加；中枢 = Σ `scenario_weights`×情景值，情景区间 = [Bear, Bull]。
2. **L2 情景档位自适应**（改写 L1 的**幅度**）：`preferences.adaptive_scenarios=true` 时按 `asset_type` 取基准 span（startup 15 / growth 10 / mature 8 / private 10 pp），再由历史波动率 `cashflow_statistics.std_growth` 覆盖（`clamp(std_g×100, 5, 20)`，取与基准的较大者）→ **仅改写 Bear/Bull 的 `growth_adj_pp`**，净利率/倍数/WACC 仍取 L1 默认。
3. **L3 舆情假设层平移**（三档同向移动）：`sentiment`.events/policy 经 `sentiment_structure()` 聚合为 `impact_map`，在 `scenario()` 内**逐档叠加**（clamp：增速/净利率/终值增速 ±15pp、WACC ±2pp、倍数 ×[0.8,1.2]）；另 **Bear 专项**：`risks` 存在 severity=high 且 impact_target=wacc 时，仅 Bear 的 WACC 再 +0.5pp。**唯一只作用于悲观档的规则**。
4. **L4 市场口径情绪因子**（平行机制，只作用于可比法）：`SCENARIO_DEFAULTS.sentiment_factor`（bear −5% / base 0 / bull +5%）参与 `sentiment_adjust()` 的 `clamp(板块热度+个股舆情+情景因子, ±10%)`；DCF 为内在价值不承受。
5. **L5 统计校验连续带**（不产离散三档）：`assets/calibration_params.json` 的 MC 先验 σ（WACC 1.5pp / 净利率 3pp / 终值增速 1pp / 倍数 σ0.2，case 级可覆盖）→ P5–P95 90% 区间；修正区间 = 情景区间 ∩ MC 90%。

**覆盖入口**（按干预强度）：`--scenarios '{"bull":{"growth_adj_pp":15}}'`（点覆盖，最高优先）＞ `preferences.scenario_weights`（改权重不改情景值）＞ `preferences.adaptive_scenarios`（改幅度）；可选 `preferences.anchor_update`（贝叶斯锚定：先验=情景权重、似然=N(情景值|外部锚,σ)，**改权重不改情景值**，主结果不变仅并列输出）。
**区间加宽的保守化机制**：可比 <3 家 → ±20%；可比质量评分 <60 → ±20%（none 占比 >50% 再 +10%）。
**双重计数警戒**：L3 的 `impact_pct` 若不为 0，会与 L1/L2 情景倍数、L4 市场口径情绪修正叠加造成中枢虚高；已计入假设层或情景博弈的信息，务必将其 `impact_pct` 归零。
- **增量重估（S5.3）**：`--compare` 输出区间变化(Δ中枢)、区间宽度变化、收敛/发散判定（|Δ宽度|>30% 判发散）；`assumption_changes` 列出真实假设差异（weights/情景参数/置信度变化）。
- 将 Step 4b 统计结论并入裁决（解读规则见上节）：若 MC 中位数与点估计方向分歧，以统计结论修正情景权重并说明依据。

### Step 6 输出估值报告（投行级，v3.4）
按**投行报告标准框架**输出（撰写规范见 `assets/report_style_guide.md`，HTML 投行版模板见 `assets/output_template_pro.html`，文本版见 `assets/output_template.md`）：

**内容结构（层层递进）**：执行摘要（KPI 三卡：中枢／情景区间／MC 90% + 三口径区间条 + 核心观点 + 推演逻辑；**不出目录、无结论条**）→ 公司概况 → 行业与竞争 → 财务数据基础 → 估值方法与假设（**含生命周期阶段与逐年预测增速数值**）→ 估值结果（双口径）→ IPO 定价约束 → 风险提示 → 结论建议 → 数据溯源与免责。

**强制要素**：
- **双口径估值区间**（情景区间 + MC 90% 统计区间 + 修正区间三口径并排，自动给出主口径规则）；

- IPO 场景含**发行定价定位**（发行估值 vs 估值区间对比）；
- **方法适用性与局限性表（v3.14）**：逐方法说明适用场景与局限（可比/交易融资/融资锚/DCF/NAV），对应"多方法交叉验证"的可解释要求；

- **startup 类标的的置信度必须做方法覆盖度校正（v3.14.2）**：`asset_type=startup` 且 `dcf_applicable=false` 时，权重集中于单一市场法，引擎自动把 `dcf` 从 `confidence.methods_available` 剔除、按 `diversity_factor = 0.5+0.5×(有效方法数/2)` 折减置信度分并**封顶 79.9（不得评"高"）**，输出 `methods_inapplicable` / `method_coverage` 供报告引用。报告中"数据完整度"与"置信度"必须分列说明——前者衡量字段齐备度，后者衡量方法与数据共同支撑度，二者不可互相替代。

## 4. 估值方法选择规则（引擎自动 + LLM 判断）

| 公司状态 | 主方法 | 辅助方法 | 备注 |
|---|---|---|---|
| 盈利 + 高成长（CAGR≥20%） | 可比 PE + PEG | DCF、PS | 科创板/创业板常见 |
| 盈利 + 稳态 | 可比 PE | DCF（主）、EV/EBITDA | |
| 未盈利 + 高成长 | PS / EV-Sales | PFCF、SOTP | 科创板允许；PE 自动禁用 |
| 重资产/成熟 | EV/EBITDA、PB | DCF、**净资产法（NAV）** | 制造业/银行券商；NAV 作主方法候选 |
| 多业务集团 | SOTP（分部加总） | 可比法 | 各分部单独选法 |
| 非上市公司（private） | DCF + **融资价格锚/交易锚** | PS、**流动性折扣** | 建议启用 liquidity；中证协四方法适用 |
| 初创/未盈利（startup） | PS + **融资价格锚** | 交易锚 | DCF 不适用（无稳定现金流）；PE 自动禁用 |

统计校验结论用于方法选择的佐证：若 DCF 权重方案导致估值大幅偏离（如未盈利公司 −20%+），报告须标注"DCF 不适用该状态公司"并下调其权重。
**v3.5 资产类型适配**：`meta.asset_type` ∈ startup/growth/mature/private 时，引擎输出 `asset_adapter`（DCF 适用性 + 主方法建议，仅提示不强制），与上表引擎化联动。

## 6. 错误与边界情况处理

完整清单见 `assets/error_handling.md`。高频场景速查：
- **一句话信息不足**：一次问清（≤4项）；**数据矛盾**：明确告知采用口径；
- **可比 <3 家**：降级 + 区间加宽 ±20% + 置信度下调；
- **亏损企业**：自动切 PS/PFCF，PE 禁用并说明；**敏感性矩阵与发行约束同步回退 PS 口径**；
- **极端倍数**：1.5×IQR 剔除并展示剔除前后；
- **DCF 终值占比 >70%**：提示终值依赖过高；
- **情绪-质量**：**v3.15.0 起已彻底解耦**（口径 B）——③市场舆情不引用质量分，原"情绪-质量背离→修正减半（泡沫抑制）""舆情错杀"交叉规则**已移除**；情绪与质量分别披露，不得回退旧交叉口径；
- **因子校准缺失**：标注"未做因子校准"，置信度−1 档；
- **统计校验异常（v3.0/3.2）**：读取 `monte_carlo.success_rate` 与顶层 `validation_passed=false` 时强制标注"统计校验未通过"；MC 区间宽于情景>±20% 置信度降档；`elasticity_issues` 非空（弹性方向异常）检查扰动 clamp 逻辑；
- **幻觉防御（X3）**：关键数字必须来自引擎/统计输出或文件原文，无法核实标注"假设值"。

## 7. 可复用性与配置化（新公司直接复用）

- **情景/权重**：`--scenarios` 与 `preferences.weights/scenario_weights` 可配置；
- **统计校准**：`assets/calibration_params.json` 提供默认先验分布与案例级覆盖（周期股 vs 未上市 AI 公司），新行业可追加 case 配置；`--calibration` 可替换校准库；

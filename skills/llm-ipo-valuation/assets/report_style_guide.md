# 投行级估值报告撰写规范（report_style_guide.md，v3.16.11）

> 本规范是技能 Step 6 报告撰写（Markdown 专业版 / `output_template_pro.html` 投行版）的统一执行标准。
> 目标读者：投行/一级市场投资人/企业决策层。风格定位：**权威、严谨、精炼、可审计**。
> 硬约束：报告全部核心数字必须来自引擎/统计输出，禁止 LLM 编造（X3 幻觉防御）。

---

## 1. 内容结构（投行研究报告标准框架，逻辑层层递进）

```
① 封面/页眉    报告编号·估值基准日·公司·板块·报告性质（拟IPO/上市复核）
② 执行摘要     结论前置：估值区间大数字 + 3 条核心观点 + 1 段推演逻辑（一页读懂）
③ 核心观点     3-5 条独立观点句，每条附"数据支撑"索引（对应后续章节）
④ 公司概况     商业模式/产品结构/经营亮点与核心矛盾（画像六模块提炼）
⑤ 行业与竞争   行业规模与增速·竞争格局（含可比组）·政策·市场热度
⑥ 财务数据基础 三年财务表·盈利质量·历史增长统计特征（CAGR/波动率/趋势）
⑦ 估值方法与假设 方法选择逻辑·关键假设表（含引擎校验留痕）·WACC/增速/倍数
⑧ 估值结果     多方法对比·修正项·情景博弈·统计校验·IPO 定价约束（双口径强制）
⑨ 风险提示     主导变量弹性·情景推演·尾部风险（分高/中/低）
⑩ 结论与建议   估值区间结论·推导逻辑·审慎参考口径·免责声明
```

**递进逻辑**：执行摘要（是什么）→ 公司/行业（为什么）→ 财务/假设（凭什么）→ 估值结果（值多少）→ 风险/结论（怎么用）。

## 2. 语言风格规范

| 维度 | 规范 | 反例 → 正例 |
|---|---|---|
| 句式 | 正式书面语，主谓宾完整，避免口语 | "估值挺高" → "估值中枢显著高于可比中位，溢价幅度需成长性论证支撑" |
| 用词 | 商务专业术语精准 | "大概30倍" → "对应 PE 30.2 倍"；"跌得厉害" → "同比下降 12.4%，毛利率承压" |
| 数字 | 精确到合理小数位，带单位与口径 | "900亿" → "综合估值中枢 972.4 亿元（对应 2025 年 PE 162 倍）" |
| 观点 | 每观点句独立成段，可被数据追溯 | 观点 + "（依据：§5.2 可比法 PS 中位 17.5 倍）" |
| 结论 | 结论前置、推导后置；结论不含模糊词 | "可能、或许" → "区间判断如下，依据如下" |
| 语气 | 权威但不夸大；不确定处明确标注 | 不确定性以"审慎口径/乐观情形"分级表述 |

## 3. 数据逻辑规范

1. **来源标注**：每个关键数字后标注来源（招股书§X / 引擎输出 / 统计输出 seed=42 / Wind 2026-08 未验证）；数据表末附"数据溯源与置信度"。
2. **口径统一**：金额=亿元、比率=小数、PE/PS 标注口径（归母净利/营收 TTM）；可比与目标同期；情景与 MC 双口径并列不混用。
3. **趋势优先**：呈现历史序列时突出变化（如"2022-2025 营收 CAGR 140%，2025 同比 +335%"）；对比优先（如"发行 PE 162 倍 vs 可比中位 80 倍，偏离 +103%"）。
4. **双口径强制**：估值结论必须同时给出**情景区间**与 **MC 90% 区间**（双口径）；若再列出**修正区间**（原始情景 ∩ MC90%）则为**三口径**。双/三口径须并列不混用，两者不一致时说明取舍依据（规则见 SKILL.md Step 4b 解读）。
5. **异常留痕**：引擎 warnings（如 WACC 偏差、三角校准偏离、行业指数偏差）须在报告对应章节显式呈现，不得静默忽略。

## 报告层引擎口径陷阱（v3.14.1，实测踩坑记录）

> 来源：通则康威（301718.SZ）报告复核。以下四类口径若不显式处理，报告会出现"读者按公式复算对不上"或"同一参数两处取值"的硬伤。

1. **可比法三个口径（pe/ps/pb）的 `value_median` 已含情绪倍数 `multiple_factor`。**
   实际公式为 `value = 倍数中位 × 基数 × scenario.params.multiple_factor`（另含 `sentiment_structure.impact_map.multiple_factor` 叠加）。
   例：64.805× × 1.95 亿元 ＝ 126.53，须再 ×1.028 方等于表列 130.07 亿元。
   → **报告的方法对照表必须在"口径与分子分母"列写出"× 情绪倍数 ×1.028"**，并说明随后 `comparable_raw` 还会乘 `total_market_adjust`（含情绪调整），二者机制重叠须在风险章节作"保留意见"披露。
   基数反解：`基数 = value_median ÷ 倍数中位 ÷ multiple_factor`。

2. **情景 WACC 必须逐情景直取 `scenarios.<name>.dcf.wacc`，不得在某一情景值上做加减。**
   构成：`wacc_used`（用户显式）＋ `wacc_adj_pp`，而 `wacc_adj_pp = SCENARIO_DEFAULTS[name].wacc_adj_pp（bear +1.0 / base 0 / bull −1.0）＋ impact_map.wacc_adj_pp ＋（bear 且存在 severity=high 的 WACC 风险时再 +0.5）`。
   实测：用户显式 9.5% → Bear 10.4%／Base 8.90%／Bull 7.9%（≠ 9.5±0.9/1.6）。
   → 表格须区分"用户显式 WACC"与"Base 情景有效 WACC"两行，并在正文列出三情景完整构成。

3. **`sensitivity.growth_pe_matrix` 与 `industry_index.implied_values` 用的是 `rev_ttm × fin.net_margin`，与主方法口径不同。**
   主方法（披露档激活时）用 `implied_margin = 披露净利 ÷ rev_ttm ± margin_adj`；若 `net_margin` 填的是"最新期净利率"，则矩阵/行业隐含值实为**跨期混合口径**（TTM 营收 × 最新期净利率）。
   → 报告须显式标注该口径差，并声明矩阵基准格/行业隐含值**不可与可比 PE 口径直接相减**。

4. **`sensitivity.wacc_sensitivity` 的三档以 `wacc_used`（用户显式）为基准**，其基准格 DCF 值低于 Base 情景点值（后者用 `wacc_adj_pp` 调整后的有效 WACC）。
   → §10 WACC 敏感性表须注明基准口径及与 §6 DCF 点值的差异来源，避免被读作"两个 DCF 值矛盾"。
6. **`gap_note` 比值判读（v3.16.8）**：`synthesis.dcf_vs_comparable_gap` = 可比法值 ÷ DCF 值，**1.0 才是一致**；不得把 gap<0.8 读作「两口径接近」（gap=0.69 即可比法比 DCF 低 31%，属实质背离）。报告层已按 |gap−1| 三档对称判读并给出偏离方向；若手工改稿须沿用同一口径。

5. **【v3.16.7 新增】`dcf_weight_cap=0` 时 DCF 仍是"有值的"——那是名义留痕值，不是估值结果。**
   引擎在金融/资源类路由下把 `weights.dcf` 归零（`framework_check.dcf_admissible=false`），但 `dcf_valuation()`
   照常执行并把结果挂在 `scenarios.<name>.dcf.equity_value` 上（中国平安 26,990.12 亿，可比口径仅 10,527.51 亿）。
   若报告照常呈现，会同时踩两个坑：① 权重 0.00 却写"两法并行"（自相矛盾）；②
   `synthesis.dcf_vs_comparable_gap = 0.39` 落入 `_build_narrative` 的"比值 <0.8 → 两口径接近、相互印证"分支，
   **把 2.6 倍背离读成"分歧小"**（金融主体 DCF 名义值恒为高估方向，比值恒 <1）。
   → 报告须按 §6.1 / §7.1 / §7.2 / §2 逐一改写措辞，并挂 `callout.alert`「方法选择结论」；
   口径关系段只描述"留痕"，不得出现"互证"。

## 详实投行版规范（v3.10，report_generator.py v2）

> 默认输出路径：`report_generator.py output.json -o report.html --stat stat.json --input input.json`
> （input 为详实版核心输入：公司/行业/财务章节与数据溯源数据源）。

- **11 段结构**：执行摘要（结论前置）→ 核心观点（数据支撑）→ 公司概况 → 行业与竞争（可比矩阵+指数验证）→ 财务基础（质量卡明细）→ 方法与假设（来源审计）→ 估值结果（多方法+综合推导+补充锚+敏感性）→ IPO 定价约束（隐含 vs 实际）→ 风险提示（警告+弹性+统计状态）→ 结论与建议 → 数据溯源；
- **§8 双口径强制（v3.16.4 强化）**：**已上市标的**在 §8 必须并列「**实际市场口径**（现价／总市值，取 `input.fundraising.market_price`／`market_cap`）」与「**模型隐含口径**（每股隐含价／中枢市值，取 `output.ipo_check.price_per_share`／`synthesis.weighted_mid`）」两行，给出偏离%与定性结论；同时以 `<p class="sub">` 标注**口径说明**——模型隐含 PE/PS 分母为 TTM（与可比中位同基），而估值中枢以预测口径利润为基数，故「模型隐含 PE vs 可比中位」的偏离含**前瞻估值 vs TTM 倍数**口径因素，非计算错误。**未上市标的**则保留「发行 PE／发行 PS／每股价格／募资额」行，不出现市场口径行；
- **版面规范**：页眉（报告编号/基准日/引擎版本）、KPI 卡片（中枢 40px 高亮卡）、三口径区间条（比例刻度）、图表编号（图 1/2/3 + cap 注释）、警告行橙色高亮/正常行绿色高亮、callout 结论框、页脚版本信息；
- **语言规范**：每章首段为背景论述（模板化定性解读），表格承载数据，callout 承载结论——数据与解读分离，解读不产生新数字（X3）；
- **审计要素**：报告编号、估算项披露、数据来源+口径列、免责声明、引擎/统计版本与 seed/n 复算参数。

## 三层计划留痕块（v3.16.0 / v3.16.1，报告呈现要求）

当输入开启三层开关时，报告须新增以下章节／表格；未开启时不得出现空表。**注意（v3.16.1）**：Layer 1（`lifecycle_mode=auto`）已由技能流程层**默认写入新案例输入**，故新报告默认须呈现 Layer 1 相关块（`lifecycle` / `growth_schedule`）；Layer 0（`layer0_check`）与 Layer 2（`industry_params`）仍为按需开启：
